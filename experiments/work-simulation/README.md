# Work simulation: TEST-прототип

Статус: observed для локального исполнения; not_validated для переноса на людей. Все данные синтетические. Кейс не описывает ЛитРес или его сотрудников.

Режим проверяет, какого вклада недостаёт при выполнении одной рабочей задачи. Четыре конфигурации отделяют эффект компетенции от эффекта доступного контекста. Это отдельный эксперимент в alashi; правила игры не меняются.

```text
Рабочая задача → четыре конфигурации → единая приёмка → профиль для проверки
                        ↑                                  ↓
            контекст и компетенция              обучение или пробная работа
```

## Что исполняется

Вымышленная библиотека меняет доступ к книге после отмены подписки. Исполнители получают исходное описание либо дополненные правила: отдельные покупки и подарки сохраняются, подтверждённый льготный период даёт доступ. Добавленная компетенция реализована отдельной задачей проверки API-контракта: она вызывает обработчик, обнаруживает нарушения и исправляет политику.

Исполнение использует существующий `runCycle` из `tools/agent-bootstrap`. Каждая задача запускает отдельный локальный Node-процесс. TEST-адаптер API проверяет зависимости и принимает нулевой расход. В нём нет production-арены, регистрации кошелька или обращения к модели. Получение корректной квитанции протокола отделено от качества решения: все четыре runs завершаются, затем независимый модуль приёмки проверяет их результат.

Поведение исполнителей задано скриптами. Контрасты сконструированы для проверки механики сравнения. Это не измерение способностей LLM или работников.

## Наблюдаемый результат

| Конфигурация | Проверка контракта | Контекст | Приёмка | Отложенные случаи | Вызовы инструментов |
|---|---|---|---|---|---|
| A | нет | исходный | 4/12 | 1/3 | 3 |
| B | нет | дополненный | 8/12 | 2/3 | 3 |
| C | есть | исходный | 8/12 | 2/3 | 5 |
| D | есть | дополненный | 12/12 | 3/3 | 5 |

У всех один набор из 12 проверок. Три отложенных случая отсутствуют в рабочих входах исполнителя. Они проверяют новые входы в пределах этого TEST-кейса; сами по себе они не устанавливают обобщение на реальные проекты.

Вклад компетенции ищется одновременно в C против A и D против B. Обе пары исправляют четыре проверки: старый клиент, отсутствующий пользователь, неизвестное состояние подписки и пустой идентификатор пользователя. Вклад контекста ищется в B против A и D против C: покупка, удаление купленной книги из каталога, льготный период и подарок.

Из этого получается проверяемый профиль: участник должен уметь проверять совместимость со старым клиентом и недопустимые входные данные, оставляя воспроизводимые контрактные проверки. Правила владения книгами нужно передать команде отдельно. Один новый сотрудник без контекста не устраняет весь дефицит.

Профиль является гипотезой о полезном вкладе. Не установлено, нужен ли найм. Следующий реальный опыт должен сравнить обучение действующей команды с пробной работой кандидата, учитывая помощь коллег и затраты людей. При пропущенной конфигурации вывод блокируется. Если появляются регрессии, положительный профиль не выдаётся. При отсутствии эффекта список компетенций остаётся пустым.

## Неявное знание

[Гипотеза Амира о биологическом рве](../../docs/200_ZETTEL/20261018-knowledge-transfer-evidence.md) сохранена как hypothesis. «Коллективное бессознательное» и «Jungian Paradox» используются как исследовательская аналогия владельца.

Отдельная TEST-проба строит таблицу решений по четырём размеченным действиям. На трёх новых случаях общее описание не задаёт решения: 0/3. Примеры разрешают 2/3; случай противоречащих обещаний остаётся неизвестным. Это сопоставление категорий, а не обучение нейросети. Референсных решений людей нет. Проба показывает, как сохранять неизвестное в отчёте, но не проверяет эмоциональный интеллект и не доказывает непередаваемость знания.

## Как запустить

Нужен Node.js не ниже 22.18, как для текущего frontend. Установка зависимостей использует существующий `frontend/package-lock.json`; новых пакетов нет.

```bash
cd frontend
npm ci
npm run work:simulate
npm run check:work
npm run work:server
```

В другом терминале из `frontend`:

```bash
ALASHI_WORK_SIMULATION_API_TARGET=http://127.0.0.1:18715 npm run dev -- --host 127.0.0.1 --port 5183 --strictPort
```

Открыть `http://127.0.0.1:5183/work-simulation`. Кнопка выполняет новый прогон всех конфигураций и обновляет результат. JSON содержит политики и события задач. В нём сохранены основания профиля. При сбое сохраняется прежний результат. В production-сборке доступен записанный TEST-результат, повторный запуск выключен. Локальный сервис принимает только фиксированный POST из локального origin, отвергает тело запроса и параллельный запуск. Он слушает только 127.0.0.1.

Канонический записанный [JSON-отчёт](../../frontend/src/work-simulation/report.json) создан настоящим исполнением. В нём есть SHA-256 исходников для воспроизведения. Это контроль соответствия файлов, а не защита от изменения репозитория. Один прогон делает 16 вызовов локальных инструментов и 0 вызовов моделей. Повторное открытие каждого завершённого журнала не повторяет работу. Аварийное восстановление и бюджет защищает существующий scheduler; новый режим не добавляет отдельной реализации этих механизмов.

## Проверки прототипа

Observed, 18.10.2026: [восемь новых Node-тестов](evidence/prototype-tests.tap) и [44 существующих теста исполнителя](evidence/existing-tests.tap) прошли. Новые тесты включают отрицательные контроли, пропущенную конфигурацию, переименование ячеек и регрессию. TypeScript и production-сборка прошли; `check:strategies` и `check:trading` прошли. Rust и SBF в этой задаче не запускались: их исходники и API арены не менялись.

Локальный браузерный прогон проверил переключение конфигураций, настоящий POST, скачивание отчёта и сохранение результата после ошибки. На ширине 390 px нет горизонтального переполнения; ошибок JavaScript нет. Скриншоты просмотрены. [Квитанция браузерной проверки](evidence/browser-check.json), [desktop](evidence/desktop.png), [телефон](evidence/mobile.png), [гипотеза](evidence/knowledge.png).

Публичного деплоя в этой задаче нет. Данных компаний в опыте нет. Реальные исполнители не проверялись; экономический эффект найма не измерен.
