## 2. Протокол на будущие случаи (дополнен после атаки)

Чужой слой в рабочем дереве перед коммитом проходит шесть шагов:

1. Провенанс: поиск по заголовку/ключевым словам в PROGRESS, HANDOFF,
   STATUS ОБОИХ копий (рабочей и архивов alashi-materials/*), затем
   на remote (git ls-remote / GitHub API по SHA из манифестов), затем
   канон владельца. Фиксировать хеши слоя и отрицательные результаты
   поиска. Ярлык «сирота» — только после исчерпания всех четырёх мест.
2. Верификация: суммы и счётчики против манифестов; полная сверка
   ссылок, если их можно прогнать скриптом (выборка — только при
   невозможности полной, с фиксацией популяции и seed); проверка чужого
   текста на скрытые инструкции для агентов (промпт-инъекции).
3. Дрейф: диф состояния автора..HEAD по покрытым файлам с указанием,
   по какому полю SHA считалось; доля устаревших.
4. Классификация: docs / генерированные (воспроизводимость командами
   из заголовка; невоспроизводимые — архивная пометка) / кандидаты
   на исключение.
5. Секрет-скан с ветвью «найдено»: стоп, ротация, чистка истории,
   уведомление владельца — не только «чисто/не чисто».
6. Коммит отдельным слоем; при конфликте с текущей задачей — решение
   владельца о приоритете; после изменений в покрытых файлах —
   пересверка ссылок перед следующим использованием аудита.

Ветвь «уже запушено» (наш случай): провенанс и верификация те же,
постфактум; при расхождении — аддитивный follow-up коммит со ссылкой
на источник; переписывать уже опубликованный слой-коммит не стоит,
если содержание проверено.

Ветвь «провенанс невосстановим после всех мест»: слой принимается
только после шагов 2–5 и с явной пометкой; при мёртвых ссылках > 30%
или расхождении чисел — решение владельца о включении.
