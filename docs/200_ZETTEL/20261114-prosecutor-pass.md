# Прокурорский проход: мутации верификатора, независимый пересчёт, рейтинг уязвимостей

Проведено 14.11.2026 ~05:15 по Астане над артефактами сесси
(world-100-grid, verify.py, цепочка доказательств 13-14.11).

## Мутационный тест верификатора (10 мутаций, два слоя защиты)

До усиления verify.py поймал 4/8 мутаций логикой; найдены и закрыты две
дыры: (1) хэши checksums.json вообще не проверялись, (2) согласование
строк games с decisions выполнялось только для игр A и C: подделка доли
l4-20261114 до 0.9 с перегенерацией хэшей проходила насквозь. После
усиления (проверка хэшей сплитов + agreement для каждой игры) все 10
мутаций ловятся; M9 (зрелый атакующий с перегенерацией хэшей) ловится
именно логическим слоем. Журнал: mutation-journal.json в репо датасета.
Слепые зоны, оставленные сознательно: поле offer_cash_visible не входит
ни в один claim (информационное); допуски полос B/C/F допускают малый
дрейф внутри себя by design; строки decisions не сверяются ни с чем
внешним внутри пакета, внешний якорь это пин коммита alashi в
checksums.json.

## Независимый пересчёт (python из сырья, минуя экспорт и parquet)

Прямо из calls/phases/snapshots сырых каталогов, отдельной реализацией:
приёмочные 224/70 с долей 8/224 = 0.035714; парные положительные
дельты 20/20; слепой перцентиль сида 20261114 = 0.4987. Совпадение с
датасетом побитовое.

## Рейтинг уязвимостей цепочки (по убыванию угрозы)

1. L4 написан рукой, без поиска по политикам: утверждение о худшем
   случае ограничено воображением разработчика. Атака: эволюционный
   поиск с fitness = доля получателя. Слабейшее звено.
2. Модельная рука пуста: «крышка держит против моделей» держится на
   qwen run 1/2 (одна модель, сторонние записи, по одному сиду).
3. Три сида L4/blind без доверительных интервалов на размер эффекта.
4. Сиды 20261101-20 последовательные, не случайная выборка пространства
   сидов; парная структура частично маскирует.
5. Перегенерация хэшей + согласованное искажение ловится agreement-
   проверкой, но сама decisions-таблица внутри пакета не имеет внешнего
   якоря кроме пина коммита.
6. Допуски полос допускают малый дрейф (by design, задокументировано).

## Prereg следующих предсказаний и kill-критерии

- P1 (поиск атакующего): эволюционный поиск политик (fitness = доля
  крупнейшего получателя, движок правил как оракул, минимум 5 held-out
  сидов) не превысит share 0.08 и HHI 0.03 ни на одном сиду. Kill:
  превышение понижает перенос «ограничение бьёт детекцию» до «держит
  против известных семейств политик».
- P2 (внешняя проверка): любой третий, взяв публичный репо датасета,
  воспроизведёт ALL CLAIMS одной командой. Kill: невоспроизводимость,
  не закрытая фиксом.
- P3 (поле): p75 INP страницы /live на реальных устройствах < 200 мс.
  Kill: RUM выше бюджета отзывает фронтенд-вывод до переработки.
- Kill-критерий переноса в продакшн: живая партия Alashi, в которой
  легальная стратегия достигает доли получателя выше 15% (удвоенная
  граница run 2), означает: крышка не работает в диком контексте.
