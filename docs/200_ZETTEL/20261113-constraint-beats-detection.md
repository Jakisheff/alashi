# Ограничение бьёт детекцию: перенос из лестницы обхода EDR

Гипотеза от 13.11.2026. Источник переноса: разбор внешнего репозитория
core-aitu/malware-ai-talk (учебные лоадеры к докладу Creating Malware with
AI, AITU 23.10.2026). Четыре образца образуют лестницу, где каждая
генерация убирает один детектируемый примитив: классический инъект с
CreateRemoteThread, затем APC на суспендед-потоке, затем захват
существующего потока без создания нового, и финал P3, где запись
шеллкода в память жертвы выполняет сама ОС через копирование
отравленной командной строки в PEB. Детекция на каждом шаге отстаёт;
последний шаг вообще не совершает «подозрительных» вызовов записи.

Переносимое правило: когда контрагент недетерминирован (агент, модель),
поведенческий мониторинг отстаёт всегда; надёжнее сузить пространство
действий так, чтобы нежелательный исход был недостижим, а не замечен.

Параллель с записанными данными ALASHI (те же числа, что в
[20261112-silent-valid-in-world100](20261112-silent-valid-in-world100.md),
другая мысль):

1. Сцена блокирует импровизацию: 1806 вызовов модели, 1805 принято,
   один вне-меню выбор отклонён каноническими правилами, статус
   completed_with_errors, точный реплей сохранён
   ([WORLD_100_BRIBE_FIX](../ops/WORLD_100_BRIBE_FIX_20261109.md)).
2. Манипуляция P3-класса уже случилась: все 72 взятки run 1 были
   легальными предложениями из меню; концентрация 58/72 = 80.56%, HHI
   0.652. Ничего незаконного детектировать нечего.
3. Фикс на уровне механизма, не фильтра: bounded exposure graph (каждый
   получатель ровно 3 появления в раунде, 18 разных партнёров за игру)
   дал 1/14 = 7.14%, HHI 0.071. Меню изменилось, поведение агентов не
   фильтровалось.

Где параллель ломается, и это усиливает позицию проекта: EDR не
контролирует «меню» операционной системы, поэтому индустрия обречена
догонять. ALASHI сам законодатель: правила ограничивают пространство
действий до хода агента. Проект может то, чего поведенческая детекция
не может в принципе, и это формулируемый питч-аргумент: сцена, а не
актёры.

Черновик карточки механизма (CC0, для публикации через FFS-поток после
проверки): название «Constraint beats detection»; источник computer
security; правило см. выше; условие применимости: владелец процесса
контролирует пространство действий (граница переноса: EDR не
контролирует ОС); цена метода: ограничение режет и полезные стратегии,
инварианты задаются заранее и измеряются (доля получателя, HHI), не
постфактум.

not_validated: одна пара игр, одна модель, descriptive comparison (так
записано в самом ops-доке); перенос из security не проверялся
экспериментом вне уже записанных данных. Первая проверка 13.11.2026:
L4-уровень лестницы (100 легальных атакующих, «богатейшему видимому»)
выдержал инвариант — 3.57% и HHI 0.0213 против границ 7.14%/0.071,
см. [WORLD_100_L4_20261113](../ops/WORLD_100_L4_20261113.md); один сид,
без обобщения. Дальнейшие шаги:
[20261113-red-team-ladder](20261113-red-team-ladder.md).
