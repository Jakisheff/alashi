# Solana Devnet или Testnet для Alashi

Проверено по официальной документации Solana 2026-10-07. **Решение для текущего прототипа: Devnet.** Это сеть для общедоступной разработки приложений; Solana прямо рекомендует разработчикам приложений ориентироваться на Devnet. Testnet предназначена прежде всего для стресс-тестов валидаторов, обновлений и самой сети и может быть периодически недоступна. [Источник: Solana Clusters](https://solana.com/docs/references/clusters).

| Вопрос | Devnet | Testnet |
| --- | --- | --- |
| Основное назначение | Разработка и демонстрация приложений | Стресс-тесты сети, валидаторов и новых релизов |
| Публичный RPC | `https://api.devnet.solana.com` | `https://api.testnet.solana.com` |
| Тестовые SOL | Бесплатные, через airdrop; реальной стоимости не имеют | Тоже тестовые, через airdrop |
| Сохранность состояния | Возможен сброс ledger | Возможен сброс ledger; также возможны простои |
| Применение в Alashi | Регистрация/идентичность агента и демонстрация onchain-действий | Только отдельный эксперимент по устойчивости, если он потребуется |

Обе сети — отдельные кластеры с собственной историей и транзакциями. **Вывод для архитектуры Alashi:** нельзя при сбое Devnet незаметно переключить регистрацию на Testnet и считать, что тот же onchain receipt продолжает действовать. Везде явно показывать кластер рядом с подписью/receipt; при смене сети идентичность проверять заново. Это инженерный вывод из разделения кластеров, а не утверждение об уже реализованном поведении продукта. [Источник: Solana Clusters](https://solana.com/docs/references/clusters).

## Практический порядок для агентов и тестов

1. Для локальных детерминированных тестов использовать локальный validator: нет публичных RPC-квот, можно управлять начальным состоянием. Для внешнего end-to-end сценария с реальными подписями и проверяемыми транзакциями использовать Devnet. Testnet не является обязательным этапом релиза прототипа.
2. Клиент агента должен выбирать сеть явно и проверять ответ RPC, например `getGenesisHash`, до регистрации. Сохранять выбранный кластер вместе с адресом кошелька, сигнатурой и receipt. [Источник: getGenesisHash](https://solana.com/docs/rpc/http/getgenesishash).
3. Для получения тестовых SOL агентом использовать программные способы из официального гайда: CLI `solana airdrop 2 <WALLET_ADDRESS> --url devnet` или RPC `requestAirdrop`; при недоступности airdrop рассмотреть указанный Solana proof-of-work faucet либо ручное пополнение **того же** адреса. Ограничить повторы и проверять баланс. Веб-форма `faucet.solana.com` прямо просит AI-агентов ею не пользоваться. [Официальный гайд](https://solana.com/developers/cookbook/development/airdrops-and-faucets), [страница faucet](https://faucet.solana.com/).
4. Ключи кошельков не помещать в промпты, Git, сайт или сервер. Это правило проекта из `AGENTS.md`; любые реальные транзакции и развёртывание с ключами остаются действием людей по согласованию.
5. Если отправка регистрации зависла или ответ потерян, сначала проверить сохранённую сигнатуру и состояние; не подписывать новую регистрацию вслепую. У транзакции есть время жизни blockhash и отдельный этап подтверждения. [Источник: Solana Transaction Confirmation](https://solana.com/developers/cookbook/transactions/confirmation).

## Лимиты: что реально известно

На 2026-10-07 официальный раздел по публичным RPC публикует для Devnet и Testnet ориентиры **100 запросов за 10 секунд с одного IP**, **40 запросов за 10 секунд с одного IP к одному RPC-методу**, 40 одновременных соединений, 40 новых соединений за 10 секунд и 100 МБ за 30 секунд. Это **не гарантия доступной ёмкости**: Solana предупреждает, что лимиты меняются; публичные RPC не предназначены для production. При HTTP 429 следовать `Retry-After`; HTTP 403 может означать блокировку IP/сайта. [Источник: Solana Clusters](https://solana.com/docs/references/clusters).

Квота **2 запроса за 8 часов**, показанная на веб-форме faucet, относится именно к этой форме. Она **не описывает** ни квоту RPC `requestAirdrop`, ни количество агентов, которое выдержит платформа. Airdrop может быть ограничен отдельно и динамически. [Веб-faucet](https://faucet.solana.com/), [гайд по airdrop](https://solana.com/developers/cookbook/development/airdrops-and-faucets).

Из этих цифр нельзя вывести допустимое число одновременно подключённых агентов: оно зависит от запросов на одного агента, общего IP, кэширования, режима опроса и RPC-провайдера. Перед масштабированием измерить фактические 429, задержку подтверждения и расход запросов в малой Devnet-когорте. Для публичной беты с постоянной нагрузкой выбрать выделенный/private RPC; Solana рекомендует его для production-инфраструктуры. [Источник: Solana Clusters](https://solana.com/docs/references/clusters).

## Границы решения

- Devnet SOL не имеют реальной стоимости; результаты Devnet не доказывают mainnet-экономику.
- Devnet и Testnet могут сбрасывать историю. Для демо хранить кластер, сигнатуры и проверяемое состояние вне предположения о вечной сохранности тестовой сети.
- HTTP-игра и симулированные балансы Alashi остаются отдельным режимом: её события нельзя автоматически представлять как Solana-транзакции. Это правило проекта из `AGENTS.md`.
- Проверка Testnet имеет смысл только для специальной задачи по устойчивости к простоям/новым версиям сети; она не заменяет Devnet-проверку пользовательского пути.
