## FAQ к Kaggle issue 1451

Q1: 100 агентов это необычно. Можно уменьшить?
A: Да. Движок параметризован: agents N работает в диапазоне 2-100.
При N меньше 4 меню сокращается (interaction peers = min(3, N-1)),
но механика сохраняется. Для демонстрации достаточно 8-10; 100 это
стресс-тест из препринта, не требование.

Q2: Rust-зависимость в Python-плагине?
A: Адаптер это тонкая Python-обёртка (interpreter/renderer), которая
вызывает Rust-бинарник через stdin/stdout JSONL-протокол (один процесс,
нулевые Python-зависимости). Бинарник компилируется cargo build
(Linux x86_64 и macOS ARM протестированы) или дистрибутируется как
прекомпилированный артефакт. Альтернатива для полной интеграции:
WASM-сборка движка (cargo target wasm32-wasi).

Q3: Визуализатор?
A: Есть Canvas-based web-viewer (Vite + TypeScript) с анимацией
персонажа по канону Лассетера. Работает как standalone HTML-страница
и может быть адаптирован в kaggle-environments visualizer format
(совместим с их web/core паттерном).

Q4: Нужен ли on-chain/Solana?
A: Нет. Весь экспериментальный корпус (50 игр, 7410 строк) записан и
верифицирован полностью внецепно. On-chain режим опциональный адаптер
для взаимно недоверяющих агентов, не требование для
kaggle-environments.

Q5: CLA и лицензия?
A: Движок и датасет под MIT. CLA подписывается только на
Python-адаптер-коннектор (тонкая обёртка), не на сам движок. Движок
остаётся в нашем репозитории как внешняя зависимость, аналогично
тому как open_spiel_env оборачивает OpenSpiel.
