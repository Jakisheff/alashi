# Зелёный набор не видит чужие аксиомы: утечка между доменами

Наблюдение из инцидента 22.11 (коммиты 9ddbee46..7a08dedc, фальсификация
hy4, исправления f2f69e6d). Зелёные прогоны не поймали два блокера и четыре
major не потому, что тесты плохие, а потому, что каждый набор верен внутри
собственных аксиом, а дефекты жили вне их.

Три аксиомы, которые протекли:

1. «Тесты изменённой зоны = applicable checks». Правка Node-файла
   проверялась Node-набором; контракт Node→арена валидируется только
   Rust-тестами арены (закрытый список полей report в
   arena/src/strategy_cycle.rs). Timestamps: арена последний раз прогнана
   до Node-правки, agent-bootstrap — после; иллюзия полного покрытия.
2. «Мок контрагента проверяет контракт». Mock api.post принимает любое
   тело: форма вызова проверена, схема валидации — нет. Контракт без
   второй стороны не существует.
3. «Наши тесты знают реальный контракт». Покрытие — модель угроз автора.
   Теста «арена отклоняет новые поля» не было, потому что закрытость схемы
   не была в модели. У адверсария модель другая — он и нашёл.

Контрмеры, введённые 22.11:

- Мутационная карта: шесть контролируемых мутантов контракта (лишнее
  поле, убранное поле, смена типа, гонка, приём реплеев, чтение фактов
  из вытесняемого журнала). Итог: мутанты M1/M2 убивала только арена
  (Node слеп), M3 — обе стороны, M4/M5 — новые прицельные тесты,
  M6 сначала ВЫЖИЛ и вскрыл дыру в собственном тесте-защите
  (фикстура не вытесняла журнал) — после исправления убит.
- Замороженный контрактный fixture tools/agent-bootstrap/report-contract.json:
  Node-тест сверяет ключи POST-тела с fixture, Rust-тест сверяет
  allowlist с тем же fixture. Смена любой стороны без fixture красит её
  собственный набор.
- tools/contract-gate.sh: изменённый интерфейсный файл требует прогона
  всех наборов, знающих этот интерфейс (драйвер → arena + bootstrap;
  egress → egress; rules → rules + arena).

Правило: зелёный сигнал осмыслен только вместе с ответом на вопрос
«чью аксиому этот набор проверяет». Мутант контракта — способ узнать
это до инцидента.
