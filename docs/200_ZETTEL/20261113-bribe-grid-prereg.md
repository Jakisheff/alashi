# Пререгистрация решётки взяток: структура, позиция, атака, модель

Заморожено 13.11.2026 ~19:35 по Астане, до запуска новых прогонов.
Существующие данные на момент фиксации: run 1/run 2 (qwen, сид 20261109,
docs/ops/WORLD_100_20261109.md и WORLD_100_BRIBE_FIX_20261109.md) и
L4-прогон на сиде 20261109
(docs/ops/WORLD_100_L4_20261113.md). Эти игры включаются в решётку как
уже существующие и помечены таковыми.

Гипотезы, которые решётка разделяет:

- H1 (структура): bounded exposure menu ограничивает концентрацию взяток
  независимо от правила выбора цели.
- H2 (позиция): выбор цели из меню смещён позицией (первый предложенный),
  не богатством.
- H3 (атака): легальный соперник «богатейшему видимому» не пробивает
  балансировку.

Руки (все через один rules-воркер, один драйвер world-run):

| Рука | Провайдер | Сид | Статус |
|---|---|---|---|
| uniform-legal | детерминированный, равномерный легальный ход, RNG от хэша промпта | 20261101..20261120 (20 сидов) | новых 20 |
| first-slot | детерминированный: взятка первому пиру из interaction_peers, если легальна; иначе как L4 | 20261109, 20261113, 20261114 | новых 3 |

Инициализация всех рук: epoch 0, 100 агентов, canonical_top4,
entry fee 10, balanced_cyclic_peers_v1, parallelism 2.

Решающее правило (заморожено до данных):

1. Основной тест, условный перестановочный нуль на каждой игре: на
   ЗАПИСАННЫХ множествах легальных предложений взяток целевой выбор
   перевыбирается равномерно внутри каждого предложения (B = 2000);
   считается односторонняя p-доля для наблюдаемых largest recipient share
   и HHI. Пробой инварианта: p < 0.05 хотя бы по одной метрике.
2. Движковый нуль (uniform-legal, 20 сидов) является референсным распределением
   метрик (квантили), не критерий пробоя.
3. Разложение HHI: ожидаемые доли равномерного-внутри-предложения на тех
   же записанных предложениях дают структурную часть; превышение над ней
   приписывается правилу выбора.
4. H2 проверяется условным перцентилем богатства выбранной цели внутри
   предложенного набора (среднее минус 0.5), отдельно по рукам.

Понижение статуса (заморожено): модель llama-3.1-8b-instruct вместо qwen
означает, что модельная рука считается структурной репликацией, не поведенческая;
сравнения поведения с run 1/2 остаются descriptive. Смена драйвера/воркера
относительно run 1/2 невозможна к бит-сравнению; сравниваются только
метрики концентрации.

Стоп-правило: при недоступности NIM (бюджет/время) модельная рука
фиксируется на фактически завершённых сидах с явной записью, каких не
хватило; локальные руки не зависят от GPU.

Поправка до данных модельной руки, 13.11 ~19:45: llama-3.1-8b-instruct
при систем-промпте v1 систематически нарушает протокол меню (6 из 7
первых вызовов вернули выдуманное `produce_goods` вместо элемента
allowed_actions; запись в calls/ прогона model-20261109, останов
provider_failure_threshold). Модельная рука переводится на копию
драйвера с усиленным формат-якорем в систем-промпте (v2: явный
запрет выдумывать действия, требование копировать объект целиком);
детерминированные руки остаются на v1-драйвере (хэш драйвера в
frozen.json различает руки). Если и v2 не даёт послушания, результатом
руки фиксируется несоблюдение протокола как измерение, без метрик
концентрации. Статус структурной репликации не меняется.
