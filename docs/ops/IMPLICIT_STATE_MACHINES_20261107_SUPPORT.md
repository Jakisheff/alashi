# Runners, clients and supporting services

Scope: source review of bots/src, indexer/src, tools/agent-bootstrap runtime modules and the donkey operator scripts. The machine is the workflow, so a client and server implementation are separate participants in one protocol, not automatically separate business processes. All transitions below are source-defined; no live transactions or model calls were made.

Static transition gaps to investigate:

1. Terminal snapshot cache can strand archival. `get` computes terminal from settled && history_complete ([indexer/src/chain_api.rs:179](../../indexer/src/chain_api.rs#L179)), calls archive once, then caches terminal even if archive write failed. `ready_value`:128 returns that entry forever while resident. Recovering storage does not cause another archive write, so close-settled continues refusing `not_archived` ([bots/src/close_settled.rs:65](../../bots/src/close_settled.rs#L65)). Eviction/restart changes this. Existing test:877 checks the archived flag on one write, not retry after failure. Model `terminal_unarchived` separately from `terminal_archived`.
2. Rust HTTP session rejection can retain an unexecutable pending action. `act_v2` clears only op_consumed=true ([bots/src/session_cli.rs:926](../../bots/src/session_cli.rs#L926)). Server preflight can return op_consumed=false for invalid action/parameters; the client will retry that same request and reject a corrected one. Node clears those definitive validation failures ([tools/agent-bootstrap/alashi.mjs:307](../../tools/agent-bootstrap/alashi.mjs#L307)). Concrete reachable example: a joined session accepts and persists {"action":"produe"}; server api.rs:2184 returns bad_action with op_consumed=false, and corrected produce is rejected locally at session_cli.rs:907. This static path was independently checked by a second reviewer; no runtime reproduction was run.
3. Donkey resolution recovery has a 20-signature window (S10). Model `outcome_unknown` and `history_unavailable` separately; pending does not mean the game still awaits resolution.

The code deliberately stops on some ambiguous money/provider outcomes. Those are valid states with manual transitions, not automatically defects. The inventory calls them out because an operator needs to distinguish them from ordinary retryable failures.
