# Epoch-2 donkey oracle operator (candidate)

Status: **draft operator wire, not live-verified**. The program candidate initializes six PDA sources through Alashi CPI, commits the selected source inside `Advance`, and reveals through `RevealDonkeyLaw` with the config PDA signer. The matching crank builds one Alashi instruction for each of those steps; it never submits external provider Commit or Reveal instructions. No epoch-2 program upgrade or successful real Switchboard reveal has yet been verified by this document. Do not start a funded Game until the reviewed release packet closes those gates.

The local helper `tools/donkey_reveal_proof.cjs` makes one gateway proof request with a 10-second timeout and rejects redirects. It sends the fixed public devnet RPC URL to the gateway, so a configured RPC path token is not disclosed. It uses the pinned SDK's Anchor encoder and writes a new mode-0600 proof file atomically; it never signs or submits a transaction. This is a source and mocked-test gate, not a successful provider roundtrip.

`tools/donkey_crank.cjs` performs one bounded step and exits, or a bounded worker repeats those same steps for up to 720 seconds. It uses the versions locked in `spike/package-lock.json` (`npm ci --prefix spike --ignore-scripts`). `inspect` reads canonical devnet Game, faction, oracle config, source and Clock accounts without a signer. `step --execute` requires an existing local mode-0600 transaction fee-payer key and a private state directory (0700); source authority is the Alashi config PDA, not that payer. It checks devnet genesis, executable Alashi program, Game/Faction PDAs, epoch 2 + Switchboard, six configured source and Oracle IDs, selected source owner/queue/PDA authority and phase. The post-grace technical abort deliberately requires no provider source. An existing address lookup table may be supplied if the transaction is too large. No endpoint URL may contain credentials.

Example nonsecret config shape (replace all placeholders with real public keys from the same already configured Game):

```json
{
  "game_pda": "<GamePDA>",
  "faction_pdas": ["<Faction1PDA>", "<Faction2PDA>"],
  "round_sources": ["<SourcePDA1>", "<SourcePDA2>", "<SourcePDA3>", "<SourcePDA4>", "<SourcePDA5>", "<SourcePDA6>"],
  "round_oracles": ["<Oracle1>", "<Oracle2>", "<Oracle3>", "<Oracle4>", "<Oracle5>", "<Oracle6>"],
  "lookup_table": "<optional existing lookup table public key>"
}
```

Set `ALASHI_RPC` to an HTTPS Solana devnet RPC, `ALASHI_CRANK_CONFIG_FILE` to that config path, `ALASHI_CRANK_KEY_FILE` to the existing local fee-payer key path, and `ALASHI_CRANK_STATE_FILE` to a JSON path inside a private directory outside Git. A reveal step additionally requires `ALASHI_REVEAL_PROOF_FILE` pointing to a new JSON file inside a mode-0700 private directory and `ALASHI_REVEAL_PAYER_PUBKEY` containing the public transaction payer. After `node tools/donkey_crank.cjs inspect` confirms committed Law and the selected source, run `node tools/donkey_reveal_proof.cjs` once; it writes exactly `signature_base64` (64 bytes), `recovery_id` (u8), and `value_base64` (32 bytes). The on-chain provider CPI verifies that proof. Do not include the SDK's provider reveal instruction in the outer transaction. Only after the separate provider and release gates, a bounded operator can start `node tools/donkey_crank.cjs worker --execute --max-seconds 720` alongside the finite bot host. The worker polls every two seconds and stops on Finished/Aborted, signal, error, or time budget. It takes an exclusive lock; inspect ownership before removing a stale lock. `step --execute` remains available for one deliberate step. No automatic Game creation occurs. Keep signer, proof and signed-transaction sidecar bytes out of shell arguments, logs and the repository.

At an elapsed Action deadline, the worker has 30 seconds to submit the single Alashi `Advance` instruction; it invokes the provider Commit CPI for the frozen round source and Oracle and pins the observed `seed_slot = Clock.slot - 1`, strictly after the latest paid attempt. Before commit the source must have zero seed/reveal slots and the provider's default/unassigned Oracle. At or after the deadline plus 30 seconds, source-backed commit+Advance is rejected; only the permissionless technical abort with complete factions and config remains. This does not claim a random draw or refund the in-game donkey fee/action. In Law, the later single Alashi `RevealDonkeyLaw` instruction invokes provider Reveal with the config PDA signer, then resolves every due ticket atomically in recorded order. If a proof is unavailable after the Law deadline and the pinned seed is older than 25 slots, the worker sends source-free Alashi `Advance` with complete faction tickets; it never recommits or invents a draw. The proof file is input to provider verification, not an operator-selected draw. No source/seed replacement or second commit is accepted. Provider withholding can lead to the distinct on-chain technical abort; it is never presented as a 40% empty draw. Old epochs keep their prior path.

Before submission the tool writes and fsyncs the signed transaction and signature in the 0600 state file, then fsyncs the private directory. A lost RPC response reuses those **same bytes and signature** while its blockhash remains valid. An unknown expired or confirmed failed signature stops for manual chain-receipt review; the operator must check the exact signature and on-chain Game/source state before removing the sidecar and restarting; the tool will not silently sign another commitment or reveal. A confirmed receipt clears the sidecar and the next invocation rereads on-chain phase. The tool reports only public identifiers and status codes, not key bytes, gateway responses or raw signed transactions.

The local gate is `node --test tools/donkey_crank.test.cjs tools/donkey_reveal_proof.test.cjs`: synthetic account decoding, phase/source/ticket checks, one-Alashi-instruction account order, strict proof-file parsing, one bounded gateway request without redirects, Law timeout fallback, and a mocked RPC lost-response retry. The program's separate local SBF tests exercise real provider CPI rejection of a forged proof; they do **not** prove a successful gateway proof, funded account lifecycle, LUT sufficiency or devnet provider liveness. Neither test gate is live oracle proof.
