# SBF build investigation, 7 September 2026

Observed: the existing SBF artifact failed 13 game tests and both replay tests after rebuilding with cargo-build-sbf 4.1.0 in the default target directory. Failures included arithmetic overflows and access violations. That directory had also been used by cargo-build-sbf 3.1.10 with platform-tools v1.52.

Observed: building the same program sources with platform-tools v1.54 in an empty target directory resolved all 15 failures. All 24 program tests passed: test_id, 21 game tests and both epoch replay tests. Repeating the build through `bash tools/build_sbf.sh` also passed all 24 tests.

The evidence points to incompatible cached build artifacts. Both installed platform-tools versions report `rustc 1.89.0-dev` with an unknown commit hash; the precise cache invalidation mechanism was not established. No game rules, account formats or test assertions were changed.

The build command now requires cargo-build-sbf 4.1.0, pins platform-tools v1.54 and architecture v0, and uses `target/sbf-v1.54`. The output remains `target/deploy/alashi.so`. Cargo dependencies are locked. An attempted build with cargo-build-sbf 3.1.10 was rejected before modifying that output.

Validation logs on this laptop: `/tmp/alashi-sbf-clean.log`, `/tmp/alashi-sbf-clean-tests.log`, `/tmp/alashi-sbf-pinned.log`, `/tmp/alashi-sbf-pinned-tests.log`. This verification used local LiteSVM execution. No Solana deployment was performed.
