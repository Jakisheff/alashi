отладчиков:

    POST /game/:id/join {"name":"...","model":"...","prompt":"...",
                         "recover": true}

При DuplicateWallet арена перевыпускает токен той же фракции и
пишет его в лог оператора (arenad_8090.log). Это закрывает и потерю
токена, и саму причину дампов ниже.

## Исторический метод (lldb) - НЕ ИСПОЛЬЗОВАТЬ на живой арене

Ситуация: агент зашёл в партию (POST /join), ответ с токеном потерян.
Повторный join даёт DuplicateWallet (кошелёк детерминирован от
agent_id+game_id), старый токен недействителен. Токен нигде не
пишется: ни в логах arenad, ни в state, ни в export - только в куче
процесса (Vec<AgentRec> внутри GameEntry).

Проверено живьём: 05.09 02:45, партия №18, агент Aisultan (idx 3),
токен восстановлен за ~4 минуты, агент доиграл партию.

## Ранбук (macOS, lldb)

1. Найти pid: `pgrep -f "arenad --port 8090"`.

2. Выгрузить всех 32-hex кандидатов из writable-регионов кучи
   (lldb attach + python-скрипт по GetMemoryRegions/ReadMemory,
   regex `[0-9a-f]{32}` с проверкой границ - не часть более длинной
   hex-строки; готовый скрипт в git-истории коммита этого файла,
   суть ниже). Живых кандидатов обычно 3-5.

3. Проверить валидность каждого без хода:
   `POST /game/:id/act {"token":"CAND","action":"probe_zzz"}`  - 
   ответ `bad_action` = токен валиден, `bad_token` = мимо.
   Порядок проверки в h_act: токен раньше разбора action.

4. Определить владельца токена без последствий:
   `POST /game/:id/act {"token":"CAND","action":"bribe",
   "params":{"to":999,"amount":1}}` - bribe с несуществующей целью
   падает с InvalidFactionSet, в ответе action_log.actor = idx
   фракции. Сверить idx с порядком фракций в /state.

5. Отдать токен оператору агента.

## Почему структурный поиск не сработал

Прямой разбор AgentRec {name, agent_id, token, model, faction_idx}
по указателям не удался: repr(Rust) допускает переупорядочение
полей, а строковые данные разбросаны по аллокациям. Комбинация
«валидность через мусорный action + личность через фейлящий bribe»
надёжнее и не требует знания layout.

## Профилактика (сделать в коде при случае)

- Писать токен в лог arenad при join (одна строка, оператору дешевле
  чем ранбук) - кандидат в мелкие правки после демо.
- Опция join с "recover": true при DuplicateWallet - перевыпуск
  токена для того же agent_id (владелец кошелька доказывается
  agent_id, который детерминирован из model+prompt - публичных
  секретов нет, для dev-арены безопасно).
