# SIM_FAIR_QUEUE_AB - A/B честной очереди рынка (П1, ТРИЗ, 05.09)

Вопрос: гонка латентностей делает внешних агентов структурно
хвостами (первый слот платит 12, хвост 1-3; localhost-драйвер
Aisultan избил туннельных 74.9M против 18.9/10.1M). Какие режимы
исполнения рынка снимают гонку, не сломав баланс?

Режимы (runner::MarketExec, --market-mode в simrun):
- sequential - прод, исполнение по прибытию (порядок = ротация);
- lottery - решения против состояния на открытии фазы, порядок
  случайный (сид-воспроизводимо);
- batch - все продажи по одной средневзвешенной цене фазы.

Серии: 3p (greedy,tactical,random) и 5p (2greedy,2tactical,random),
epoch 90s, 300 партий, сиды 4217/4219 - одинаковые между режимами.
Файлы: data/sim/fq_{3p,5p}_{sequential,lottery,batch}.jsonl.

## Результаты

|---|---|---|---|---|---|---|
| побед greedy | 255/300 | 256/300 | 81/300 | 234/600 | 249/600 | 106/600 |

| премия первого продавца | +6.7M | +6.7M | 0.0M | +13.6M | +13.8M | 0.0M |

## Чтение

1. LOTTERY НЕ МЕНЯЕТ БАЛАНС: иерархия стратегий, лицензии 300/300,
   взятки, выплаты - всё в пределах шума сидов. Премия первого
   продавца сохраняется (+6.7/+13.8M), но её получатель случаен:
   справедливость лотереи вместо справедливости латентности. Для
   живой арены это значит: внешний агент получает первый слот с
   вероятностью 1/n вместо никогда.
2. BATCH УБИВАЕТ ИГРУ: премия первого снята, но лицензии не
   продаются ВООБЩЕ (0/300) - при равномерной выручке никто не
   собирает кассу для бида; выплачивается в 2-2.5 раза меньше
   (нет ренты 30-40M), взятки исчезают. Причина падения сумм
   выплат - не средняя цена (она не меняется), а смерть рынка
   лицензий и каскад за ним. ОТКАЗАН данными.

## Рекомендация

- В прод после демо: LOTTERY (окно сбора решений на открытии фазы
  + случайный порядок исполнения). Реализация в HTTP-арене:
  буферизация market-действий первые N секунд фазы, затем
  исполнение в случайном порядке - отдельная задача, демо не
  трогаем.
- Batch закрыт: противоречие решено ценой системы (лицензия -
  наш главный актив-драма).
- Записано по правилу «одна правка за раз»: сначала lottery в
  живой арене, следующая A/B (кредит П6) - только после замера
  lottery вживую.
