# One world with 100 model-driven factions

Implementation and first-run evidence for Amir's request on 9 November 2026.
The first live game completed on 9 November 2026. No NVIDIA instance or credit
was used for this workflow. Provider cost in USD was not measured.

## Intended result and boundary

Run 100 independent agent identities in one six-round ALASHI game, sharing
the same market, laws, resources and settlement. Each agent requests its own
decisions from BitLLM. The canonical Rust rules validate those decisions.
This is an isolated off-chain experiment with simulated money. It does not
register players in the public arena or alter a deployed Solana game.

An explicit experimental admission path allows up to 100 factions. Ordinary
admission retains the six-faction cap. The worker uses the existing simulator,
actions, phase transitions, voting and settlement. Raising the global cap was
rejected because it would affect the on-chain contract and fixed-size oracle
structures unrelated to this experiment.

The world pauses while model decisions are collected. A frozen seed determines
execution order; model/network response order does not determine who moves
first. Actions are still applied sequentially through the existing rules, so
earlier market actions can affect later ones. This is an explicit experimental
execution policy, not a claim of equivalence to real-time public play.

The existing economy is preserved, including the falling market price and
four-place payout schedule. A 100-player run may expose concentration or
market saturation; those observations do not authorize a silent redesign.

## Acceptance evidence

- Exactly 100 distinct registered factions in one worker state.
- Complete six-round phase sequence, including votes and president veto
  opportunity, and a canonical final settlement.
- Separate counts for requested model decisions, valid answers, accepted
  actions, rejected actions and unknown usage. A finished world alone does not
  prove that every model call succeeded.
- Per-agent decisions and receipts, shared state hashes and deterministic
  replay of saved phase batches.
- Sum of payouts and rake matches the settlement pot; simulated wealth and
  entry/payout accounting are reported separately.
- Frozen provider settings, bounded concurrency and budgets, crash-safe
  receipts and no automatic repeat of an ambiguous model call.
- Ordinary six-player admission and Solana behavior remain covered by their
  existing tests. New boundary tests cover capacity, invalid batches and replay.

The main risk is falsely labelling a scripted or partially failed simulation
as a successful 100-agent model run. Trace model response -> parsed decision ->
canonical action receipt -> state change -> final report. Provider token usage
and model identity remain reported by the peer, not independently attested.

## Result

**Completed:** all 100 identities played one common six-round game through
BitLLM. All 1,806 responses produced accepted canonical actions. No parser or
provider errors, rejected actions, skipped decisions or unknown token usage
were recorded. The temporary BitLLM process was stopped after verification;
its private state was retained outside the repository.

### Settlement and observed behavior

All amounts below are simulated game units, converted from micro-peso. The
bank was 100 × 10 = 1,000. Canonical payouts totalled 950 and rake was 50;
their sum exactly matched the bank. Game cash is a ranking measure and is
separate from the entry-funded payout bank.

| Rank | Player | Final game cash | Payout |
|---|---|---:|---:|
| 1 | agent-043 | 300 | 475 |
| 2 | agent-047 | 41 | 285 |
| 3 | agent-051 | 38 | 142.5 |
| 4 | agent-061 | 36 | 47.5 |

The other 96 players received zero payout under the existing four-place rule.
No payout schedule was changed for the 100-player experiment.

There were 405 sales, one purchase, 416 production actions, 72 bribes, 502 votes,
four vetoes and 406 explicit passes. These categories sum to 1,806 actions.
After the first 100-player sale phase, cash ranged from 2 to 22 and the shared
price reached its floor of 1. Later players therefore faced a materially
different execution price despite choosing against the same phase snapshot.

Player 43 received 58 of the 72 bribes, totalling 290, and finished with cash
300: sales 23 − purchases 3 − outgoing bribes 10 + incoming bribes 290.
This does **not** establish superior strategy: the experimental menu
offers bribes only to the richest rival, most influential rival and next player,
which can concentrate transfers toward an already prominent actor. This is a
specific interface bias as well as a limitation of using one shared model.

Decision quality is also limited. The final action phase included 12 production
actions although no market phase remained and goods do not enter final rank.
All four vetoes were redundant: rounds 3–6 already had weighted yes/no totals
44/59, 24/94, 30/132 and 10/162. For example, the round-3 10% tax would have
failed without the veto. Veto and production have no direct cash cost here;
these observations show unnecessary actions, not proof of a costly mistake.

**Conclusion:** the implementation and first live party establish that 100
stateful identities can complete this bounded shared-world mode on the school
Mac using BitLLM, with exact engine replay and correct settlement. They do not
establish economic balance, diverse independent models, strategic competence,
on-chain capacity for 100 players or public spectator support for this mode.
Before comparing strategy strength, run a separately frozen experiment that
balances recipient choices and varies seeds/order; do not edit this completed
run or interpret the winner as evidence that the current menu is neutral.
