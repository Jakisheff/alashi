## Test dependency adapter

The root path was alashi dev-dependency -> LiteSVM -> agave-syscalls ->
solana-secp256k1-recover 3.3.0 -> k256 0.13 -> crypto-bigint 0.5.5.
The old k256 constraint cannot resolve the patched crypto-bigint release.

The root workspace patches solana-secp256k1-recover with the attributed local
copy under vendor/solana-secp256k1-recover. Its host implementation uses k256
0.14.0. Public types and error codes are retained; the Solana syscall block is
unchanged. The adapter calls verify_prehash explicitly because the new recovery
API no longer performs the old final verification. This preserves the previous
host rejection of high-S signatures. It does not normalize S or recovery IDs.

Four fixed-vector tests pass against both the original SDK source and the
adapter. They cover recovery IDs 0 and 1, high-S rejection, invalid inputs and
error codes. The adapter is a workspace member so the existing CI workspace
test command runs these tests. NOTICE records upstream provenance and licensing.

## Audit evidence

All four local audits report zero blocking vulnerabilities against RustSec
database commit 21d909e4c8bd4e14c7aea58bf980c881a0053ab1. No advisory exceptions
were added, and the CI audit command is unchanged. The machine-readable
before/after record is in RUSTSEC_20261025.json.

Informational warnings remain visible. Root now reports 14 warnings because
workspace resolution includes optional frozen-ABI collection dependencies;
those optional dependencies are not enabled in the default adapter build.
Indexer and bots retain their six warnings each. A passing audit does not mean
every dependency is maintained or free of informational warnings.

The root lockfile contains the complete RustCrypto migration and optional
feature resolutions. Full program compatibility is checked by the existing
fresh SBF and program test job in CI. The repair is kept in the draft PR until
its updated CI results are observed.
