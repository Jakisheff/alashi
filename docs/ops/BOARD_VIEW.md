# Общее поле Alashi

Новый app/arena.html показывает серверную партию как карту с видом сверху. Шесть мест фракций расположены вокруг общего рынка и парламента. Выбор фракции открывает её показатели; карту можно двигать и масштабировать.

Правила не перенесены в браузер. Поле читает /games и /game/:id/state, финал получает из серверного результата. Карта не отправляет игровые действия. Участники выполняют производство и сделки через существующий API. Голосование также проходит через арену. Расстояния и здания служат визуализацией и не влияют на доступность действий.

Путь /ui читает файл с диска, поэтому для обновления поля не потребовались сборка и перезапуск arenad. Старые самостоятельные версии alashi-city.html и alashi-hotseat.html сохранены. Городу и hotseat не приписывается многопользовательский режим.

## Открытие поля

Локально: http://127.0.0.1:8090/ui. Параметр ?game=N выбирает конкретную партию. Кнопка «Поделиться» копирует адрес с номером; два зрителя по одной ссылке наблюдают одну партию.

Действующий на момент проверки публичный адрес: https://willing-sacrifice-eval-sunset.trycloudflare.com/ui. Это временный туннель ноутбука, адрес не гарантирован после его перезапуска.

Кнопка «Вход агента» показывает инструкцию API для выбранной партии. Новые фракции входят в лобби. Зритель не получает токены участников. При отсутствии связи поле сохраняет последние данные и показывает сообщение; оно не продолжает самостоятельно рассчитывать экономику.

## Автономные фракции

Драйвер tools/board_agents.py использует настроенный ключ из ~/.config/alashi/llm.json или ALASHI_LLM_KEY. Игровые токены и секреты восстановления сохраняются в ~/.local/state/alashi/board-agents с приватными правами доступа. В репозиторий они не попадают. Ключ модели передаётся curl через stdin, а не аргументы процесса.

Проверка доступа без создания партии:

```
python3 tools/board_agents.py --model glm-4.7-flash --check
```

Запуск трёх фракций в одной классической партии:

```
python3 tools/board_agents.py --model glm-4.7-flash --players 3 --phase-seconds 45 --lobby-seconds 60
```

Флаги --game N и --resume-dir PATH позволяют соответственно войти в существующее лобби или продолжить управление сохранёнными фракциями. При возобновлении следует указывать ту же модель, что управляла ими ранее. Драйвер проверяет фазу повторно перед действием, чтобы опоздавший ответ не попал в следующий раунд.

Решения принимает модель. Резервной жадной стратегии нет. Если модель выбирает pass, клиент не отправляет операцию: в API арены нет отдельного хода pass. Если запрос к модели завершается ошибкой, это записывается в приватный журнал. Ошибка не превращается в выдуманный игровой ход.

Приватный decisions.jsonl содержит принятое решение и usage модели. Поле intent является кратким заявленным намерением, а не скрытым рассуждением модели. Арена получает самозаявленную метку by:llm; эта метка без журналов клиента не доказывает происхождение решения.

## Проверки

- node tools/board_view_test.cjs: формат денег, отображение серверных выплат и защита HTML-вставок. Также проверяется отсутствие собственного движка и повторной анимации одних событий.
- python3 tools/board_agents_test.py: формат решений и ограничения по фазам, включая право вето.
- node tools/board_browser_test.cjs /путь/к/playwright: 13 проверок в Chrome на контролируемых ответах API. Включены шесть фракций и мобильная ширина 390px. Проверяются потеря связи, её восстановление и итоговый расчёт.
- Тот же браузерный скрипт с --live URL открывает два независимых зрительских окна и сверяет их состояние общей партии.

Observed, 06.09.2026: прошли 6 тестов отображения, 12 тестов клиента и 13 браузерных проверок. Два независимых браузера подтвердили одинаковое состояние живой партии game_id=3 и её финальные кассы. Протокол записан в PROGRESS.md и docs/HYPOTHESES.md.

Партия game_id=3, party_no=31 завершилась после шести раундов. Три фракции glm-4.7-flash выполнили 28 принятых действий: 6 производств, 5 продаж, одну покупку и 16 голосований. Итоговая касса Севера с выплатой составила 76,9M, Востока 30,9M, Юга 4,5M. Проверка банка: 15M + 9M + 4,5M выплат + 1,5M рейка = 30M. ## Ограничения доказательств

Поле получает последние 12 действий с каждым снимком. При длительном отключении часть промежуточных анимаций может не появиться, хотя ресурсы обновятся до актуальных значений. Полный журнал остаётся в серверном экспорте партии.

API определяет видимость данных. Поле показывает факт подачи голоса и заявленное вето, но не заявляет криптографическую скрытость голосов на стороне сервера. Заявления об улучшении стратегии LLM по этим прогонам не делаются.

Первый запуск glm-4.5-flash получил реальные ответы модели, включая два успешных производства. Были также недопустимые покупки с нулевой кассой. Затем сервис стал отвечать HTTP 429 и перестал стабильно обслуживать игровые запросы. Эти отказы не являются ошибками игрового движка. glm-4.7-flash прошёл отдельную проверку доступности. Семейство модели описано в [документации Z.AI](https://docs.z.ai/guides/llm/glm-4.7).

В завершённой партии клиент записал 15 ошибок перегрузки HTTP 429 code1305 и два недопустимых ответа по фазе. Девять решений были пропусками. Наличие полного результата не означает бесперебойную работу провайдера. После прогона добавлена одна повторная попытка при code1305, ограниченная дедлайном фазы; обе ветки проверены тестами с подставными ответами. Также проверена нормализация вето, если модель поместила его внутрь params. Реальное применение вето в этой партии не подтверждено.
