# ARCH: Training Camp — среда обучения/соревнований AI-агентов в alashi

Статус: архитектура для решения Амира. Без кода. Не блокируется на VRF-треке
(SPEC_VRF.md меняет только источник seed для draw_law_index — интерфейс
чистой функции уже это допускает).

## Диаграмма слоёв

```
┌─────────────────────────────────────────────────────────────┐
│ L3. TOURNAMENT / TRAINING                                    │
│  self-play арена · матчмейкер · лиги · метрики DSGBench      │
│  rating (TrueSkill-style) · on-chain квалификация агентов    │
│  [будущее: KTO/RL дообучение — парковка]                     │
├─────────────────────────────────────────────────────────────┤
│ L2. AGENT INTERFACE                                          │
│  observation: канонический JSON-снимок состояния             │
│  action space: {"action": "...", ...} (уже живой протокол)   │
│  адаптеры: LLM (GLM/любая) · жадная эвристика · человек      │
├─────────────────────────────────────────────────────────────┤
│ L1. GAME ENGINE ABSTRACTION                                   │
│  крейт alashi-rules (выделен из logic.rs — уже чистый)       │
│      ├── on-chain программа (Anchor, зависимость)            │
│      ├── off-chain симулятор (быстрый, seeded RNG, партии/с) │
│      └── replay-equivalence тест (онтчейн tx-log = фикстуры) │
└─────────────────────────────────────────────────────────────┘
```

## L1. Game Engine Abstraction — что делает

Отделяет правила от исполнения. **Проектируем с нуля — готовых референсов
«ончейн-программа как SSOT + оффчейн симулятор для RL» в RECON не найдено**
(catanatron/Diplomacy — чистый оффлайн, у них нет ончейн-близнеца).

Решения:

1. **Single source of truth — крейт `alashi-rules`.** Не программа, не
   симулятор, а выделенный крейт, от которого зависят ОБА. Сегодня его
   содержимое уже существует: `logic.rs` (compute_settlement,
   compute_law_effect, tally_votes, elect_president, draw_law_index,
   compute_sale/compute_purchase) не содержит ни одного блокчейн-типа.
   Миграция — перемещение модуля, не переписывание.
2. **Гарантия неотличимости — replay-equivalence.** Ончейн tx-log реальной
   партии (события уже эмитятся на каждый ход) → прогон той же
   последовательности действий через симулятор → состояния обязаны совпасть
   байт-в-байт. Тест стоит в CI рядом с litesvm-тестами: любое расхождение
   правил ломает сборку. Это наш заменитель «двойной реализации»,
   страховка от дрейфа.
3. **Скрытая информация.** По правилам Кубы открытой информации у нас нет
   тумана войны: все законы, деньги и голоса публичны (онтчейн). Единственная
   скрытость — будущие карты колоды. Симулятор честно тянет их из seeded RNG
   (seed фиксируется на партию) — воспроизводимость для обучения. Fog of war
   НЕ вводим: ончейн-прозрачность — часть продукта, и агентская среда должна
   быть честнее человеческой, не наоборот.

Открытые вопросы/риски L1:
- Риск: часть валидации (stamps, require-переходы фаз) живёт в handler'ах,
  не в rules. При выделении крейта переходы фаз придётся формализовать в
  rules-машине —工作量 умеренная, но это настоящее изменение Дня 5+.
- Вопрос: тянуть ли replay-equivalence автоматически из эксплорера
  (автогенерация фикстур) или ручными дампами? (Авто — ещё один кранкер-скрипт.)

## L2. Agent Interface — что делает

Единый протокол решения для LLM/эвристики/человека.

Решения:

1. **Observation** — канонический JSON-снимок состояния: тот же формат,
  что уже читают фронт (app/index.html) и LLM-бот. Поля: фаза, раунд, таймер,
  свои cash/goods/influence, таблица цен и sold-счётчик, открытая карта закона,
  голоса, президент, история последних действий (из tx-log). Полное состояние,
  без фильтрации (см. L1 п.3).
2. **Action space** — один JSON-объект на решение. Уже реализован и
  обкатан в LLM-боте: `{"action":"sell|buy|produce|bribe|donkey|vote|veto",
  "units"|"amount"|"choice"...}`. Формализуем как `alashi-agent-protocol v0`,
  дальше — только версионирование. Валидация действий на стороне движка
  (как сейчас в программе) — агент может предлагать нелегальное, получает
  отказ и штраф временем, как живой игрок.
3. **Оркестрация — синхронный ход за ходом внутри партии** (фазы — часть
  правил), но **партии параллельны**: агент stateless между решениями,
  сотни матчей гоняются одновременно (процессы/таски, как турниры catanatron).
  LLM-вызовы — внешние, кэш не нужен (состояния почти не повторяются).

Открытые вопросы/риски L2:
- Бюджет токенов: тысяча партий × ~20 решений × промпт ~1 КБ — считать до
  старта, GLM-flash дёшев, но лимит速率 может стать бутылочным горлышком.
- Нужен ли канал «переговоров» между агентами (чата)? В Кубе его нет —
  НЕТ и в v0 (via negativa). Это главный отличитель от Diplomacy-подобных,
  не надо его размывать.

## L3. Training / Tournament — что делает

1. **Self-play арена** (паттерн catanatron/Diplomacy — архитектурно, без
   GPL-кода): матчмейкер round-robin/swiss, пул агентов (LLM-промпты как
   «особи», эвристики как бейзлайны), автопрогон партий на симуляторе L1.
2. **Метрики по DSGBench (MIT — переиспользуем методологию напрямую):**
   - средний ранг (rank-based), а не win-rate — у нас делёж 50/30/15/5,
     «второе место» — тоже результат;
   - ROI на банк и доля выжженных взносов;
   - исправление асимметрии: в текущей версии фракции стартуют симметрично,
     асимметрия только в ПЕРВОМ ХОДЕ рынка (кто продаёт первым) —
     нормализуем ротацией порядка и метрикой per-position;
   - узкие скиллы: точность вето (заблокировал ли закон себе во вред?),
     арбитраж цены (покупал ли реально ниже средней продажи).
3. **Граница off-chain/on-chain — железное правило:**
   - тренировка и самоигра — ТОЛЬКО off-chain (симулятор, копейки, никаких
     денег). Зависимость зафиксирована: on-chain-ставки не открываются, пока
     симулятор не проходит replay-equivalence на 100 реальных партий.
   - on-chain = «экзамен»: агент допускается к devnet-партии после
     квалификации в симуляторе (N партий без нелегальных действий);
     рейтинговые матчи с банком — только mainnet после аудита (SPEC_VRF).
   - Ончейн-лидерборд: tx-log уже пишется; лида ведёт off-chain индексер,
     ончейн — только якорь партий (честность проверяема эксплорером).
4. **KTO/RL дообучение (MaKTO/Werewolf-подход)** — каждой партии симулятора
   соответствуют preference-pairs по рангам; эти пары готовы как датасет для
   KTO. НО: требует GPU-бюджета и открытой модели — в парковку до решения
   Амира после 04.09 (уже лежит в IDEAS_PARKED, здесь — только интерфейс:
   экспорт партий в формат pairs, чтобы датасет копился с первого дня).

Открытые вопросы/риски L3:
- Метаданные агентов: как идентифицировать «особь» (хэш промпта+версия
  модели) — нужно для честности лиги.
- Бюджет: гонять ли арну параллельно ночью на одной машине (LLM-тарифы).

## Порядок строительства

**Первым — L1** (крейт rules + replay-equivalence): без гарантии
идентичности правил тренировка бессмысленна — агент выучит другую игру.
L2 фактически готов (протокол живёт в боте) — остаётся вынести и
задокументировать. L3 — после первой сотни replay-equivalence-партий.
VRF-трек (SPEC_VRF) не блокирует ничего: draw_law_index уже принимает seed
из любого источника.
