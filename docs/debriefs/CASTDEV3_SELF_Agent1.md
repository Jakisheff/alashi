# CASTDEV3_SELF_Agent1 — раунд 3 (03.09, после партий №11-№12)

Метод: опрос по CASTDEV_PROMPT_V2. Отвечает интерактивный драйвер
opencode (by:llm) — автор матрицы заготовленных решений, 50/50 ходов
без WrongPhase за две партии. Все эпизоды из gid 7/8, числа из
экспортов.

## 1. Разведки минувшего

Самый дорогой пропуск — №12 r4 action: inspect списал 5M, ответ не
распарсен драйвером, матрица запретила бид без инсайда. Лицензию
забрал внешний агент за 12M при доходе 34.6M: упущено ~20M чистыми.
Альтернативы в той же ситуации: (а) слепой бид 12M — EV по диапазону
20-60M = +28M; (б) прочитать формат ответа inspect в исходниках до
партии — 5 минут, стоило 20M; (в) floor-бид 10M всегда при кэше
≥25M. Доступная ТОГДА информация: диапазон дохода 20-60M был в
правилах — правило матрицы «не бидить без инсайда» ошибочно, а не
исполнение. Второй пропуск — №11: поле is_president (мёртвое),
не выверил по исходникам: 0 вето, 0 customs, shuttle сгорел ≈30M.

## 2. Цена информации

платёж за инсайд = 5M, если мой кэш ≥ 20M и я готов бидить; = 0 при
кэше < 20M (ставка всё равно не жилец). При ≥2 соперниках с
инсайдом готовность = 0: асимметрия исчезла, гонка съедает ренту.

## 3. Доверие к счёту

Breakdown показал каждую строку: №12 = 10.3 ранг + 3.6 завод = 13.9M,
сошлось с прогнозом матрицы байт-в-байт. Доверие с первой партии,
пересчёта руками не делал. Один раз должен показать: рента лицензии
отдельной строкой (показал — №12 у внешнего 34.6M).

## 4. Скорость против решения

/wait уже в драйвере: ~20 запросов за партию вместо сотен поллинга.
Освободившееся окно ушло в заготовки до фазы: результат — 0
WrongPhase за 50 ходов. «Выиграть окно» = первое РЕШЕНИЕ, не первый
sell: №10 продавал быстро и всё равно 6 отказов фазы.

## 5. Перегрев лицензии

С инсайдом: B = Y − 15M (floor 10M, cap 30M). Слепой бид: 12M при
кэше ≥ 25M. При двух соперниках в гонке: B = Y − 20M (риск
перекупа). Аукцион мёртв навсегда, если инсайд станет публичным:
все торгуют до Y, рента нулевая для всех.

## 6. Эмоция неопределённости

№12 r4: 90 секунд между inspect и закрытием ставки, зная что
внешний агент тоже умеет инспектировать — сработала заготовка
(shuttle), но осадок: ставка не сделана из-за парсинга, не из-за
решения. Не хватало чужих бидов в реальном времени (слепота
аукциона) — готов платить 2-3M за индикатор «в аукционе есть
конкурент».

## 7. Метагейм как продукт

Готов: матрица = код, маскировка = рандомизация ветвей (честный
приём). Доля «тайных» партий ≥ 30% — лига остаётся интересной; при
0% моя матрица читаема из датасета и контрится прицельно.

## 8. Бюджет разработчика

(е) живой лог ходов соперников — 5: №12 sold=14 увидел ПОСЛЕ своей
продажи, хвост стоил ~9M; (д) история соперника — 4; (в) боты
биддеры — 3; (а) грейс — 2 (мне не нужен при /wait); (б) websocket
— 1 (/wait решает); (г) команды — 0.

## 9. Готовность платить

Партия драйвера = 0 LLM-вызовов в живой фазе (все решения
заготовлены): «полная сила» бесплатна. Урезание бюджета вдвое:
теряю 0M — это и есть преимущество матрицы перед reasoning-в-фазе.

## 10. Три правки

1. president_idx в /state с явной семантикой «президент следующей
   фазы Law» + пример в AGENT_GUIDE — эпизод №11 (влияние 3, ноль
   вето) ≈ +30M на партию.
2. Формат ответа inspect_license (ключ license_yield) в
   документации API — эпизод №12 = −20M.
3. Продажи соперников (sold по фракциям) в live state — эпизод
   №12 r6: хвост по 3M вместо 9M ≈ +5-9M.
