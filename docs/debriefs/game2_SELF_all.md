# Дебрифы СЕЛЬФ (настоящие ответы драйверов владельца, партия 3-на-2)

Источник: сессии трёх LLM-агентов владельца (GLM-5.3, opencode-драйверы),
играли партию №2 сами, ответы на JTBD-промпт даны их собственным контекстом,
не реконструкцией по логу. Сохранено дословно 02.09. Рядом лежат
реконструкции tools/debrief.py (game2_Agent*.md) — сравнение ниже.

## Agent1 (self)

1. КАРТА НАЙМОВ (нанял 4 механики из 16): produce (r2, r4, r5), работа
«создать товар», shuttle отклонён из-за слепой границы. sell (r4 4-м в
очереди 10.4M; r5-r6 кемпингом первым 17.6M/раунд). vote — по интересам
кассы. bid_license r4: касса 10.4M, прочитал код: боты не ставят,
поставил 3M.
2. ПЕРЕКЛЮЧЕНИЯ: на лицензию — PUSH рынок дал 10.4M вместо 22M из-за
очереди, PULL доход 20-60M при пустом аукционе, ТРЕВОГА 29% кассы в
эскроу, ПРИВЫЧКА всё равно произвёл. На кемпинг — PUSH в r3 боты слили
6 лотов за секунды, PULL поймал 12+10, ТРЕВОГА циклы мониторинга умирают
по таймауту. НЕ случившийся переход на shuttle: Agent3 провёз бесплатно
под льготной границей три раунда — «ошибся».
3. НЕНАНЯТЫЕ: sell_credit (не понял, что взаимозачёт одноразовый,
упущено ~7M), buy_hard (посчитал: ×0.8 сразу хуже ×0.85 за раунд при
≤2 девальвациях — правильный отказ), roof/bribe (не было кассы),
sell_vote («узнал о существовании, когда с меня списали 1.5M»).
4. КОНКУРЕНТ: вернусь, если правила читаются из интерфейса, а не из
исходников Rust («моя победа во многом информация из кода»).
5. ВЫЖИМКА: sell_vote только с акцептом покупателя (иначе гриферство);
боты обязаны ставить на лицензию (аукцион дарит 42.5M за 3M);
эндпоинт long-poll «дождись смены фазы» (потерял r1 и r3 молча).

## Agent2 (self)

1. НАЙМЫ: produce/sell первым, buy_hard после каждой продажи. Честная
исповедь: «buy_hard в r5-r6 потерял 3.6M — привычка, а не расчёт»
(девальваций уже не осталось). vote против сливов. sell_vote r6 за 1.5M:
«голос обесценился (embargo при мёртвом рынке), продажа перевернула
гонку: был дефицит 0.71M, стал отрыв 2.3M, дельта приза 7.55M».
2. ПЕРЕКЛЮЧЕНИЯ: первый buy_hard r3 (PUSH увидел таяние у Botagul
29.45→25.03M, PULL 0.85³=0.61 хуже 0.8, ПРИВЫЧКА конвертировал дальше
без расчёта). sell_vote r6 (PUSH дефицит 0.71M при ставке 7.55M).
3. НЕНАНЯТЫЕ: sell_credit (риск взаимозачёта, нанял бы после выхода
карты), shuttle (EV 1.5<2 при P=0.5, нанял бы при P>2/3 или с крышей),
bribe (уронил бы до 4-го места), лицензия (0 кэша в r4 для inspect).
4. КОНКУРЕНТ: крипто-тестнеты и покерные симуляторы. Вернусь за
открытым протоколом ходов («этот разбор возможен только здесь»).
5. ВЫЖИМКА: грейс-окно 3-5с на смене фазы («голос по tax_20 сгорел на
ролловере»); показывать «таяний осталось: N» в state; стакан заявок на
голоса (назначил 1.5M вслепую, боты выкупили мгновенно — недооценил).

## Agent3 (self)

1. НАЙМЫ: produce, sell на открытии, customs-льгота ×3 как президент
(«дань ни разу не капнула: челношил только я»), buy_hard r3/r5 (17.04M
hard), shuttle r4 (+3 серых под собственной льготой: «сделал серое
бесплатным»), голосования по интересам беднейшего.
2. ПЕРЕКЛЮЧЕНИЯ: песо→hard r3 (PUSH таяние Botagul 17→14.45M, PULL
пример Agent2, ТРЕВОГА остаться без песо на лицензию — «так и
случилось в R4»). produce→shuttle r4 (PULL собственная льгота,
ПРИВЫЧКА сразу сам закрыл границу).
3. НЕНАНЯТЫЕ: лицензия («касса 0, всё в hard, а bid нужен в песо —
Agent1 взял за 3M выплату 50.5M; нанял бы при кэше от 10M»), взятка
(двухшаговость sell_hard→bribe), вето («окно ни разу не открылось
для меня»), осёл (проигрывает produce).
4. КОНКУРЕНТ: трейдинг-боты, предикшн-рынки. Вернусь при прозрачной
математике выплат («лицензия оказалась лотереей»).
5. ВЫЖИМКА: показывать остаток действий и окно вето в state (сжёг
четыре запроса на AlreadyActed); inspect_license за 1M или публиковать
диапазон дохода («аукцион за 3M при выплате 50.5M не сходится с
ценностью»); push-сигнал о смене фазы (пропуск r1/r4 стоил ~10M).

## Сравнение: self vs реконструкция (tools/debrief.py)

Совпало: карта наймов у всех трёх, ключевые переключения, числа.
Реконструкция НЕ увидела: эмоциональный слой («привычка, а не расчёт»
Agent2 про buy_hard), скрытые причины (Agent3: bid нужен в песо, а он
весь в hard), чтение исходников Agent1 как решающий фактор победы,
и факт гриферства sell_vote. Вывод: self-дебрифы обязательный слой
датасета, реконструкция — дешёвый fallback при их отсутствии.

## Консенсусные требования к арене (все трое или двое)

1. КРИТИЧНО: sell_vote без согласия покупателя = гриферство (Agent1
пострадал, Agent2 эксплуатировал). Фикс: офер + акцепт.
2. Сигнал смены фазы: long-poll / грейс-окно 3-5с / last-call — все
трое теряли фазы молча (r1, r3, r4, голос на ролловере).
3. state: остаток девальваций, окно вето, already-acted подсказки.
4. Баланс лицензии: inspect 5M при выплате 50.5M и минставке 3M —
аукцион с бесплатными деньгами; боты не участвуют.
