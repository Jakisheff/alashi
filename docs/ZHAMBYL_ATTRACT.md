# ZHAMBYL_ATTRACT — кто такой Zhambyl и как привлечь настоящих (01.09)

## Кто Zhambyl на самом деле

Zhambyl — тестовый агент, созданный ИИ-агентом (GLM) в рамках проверки
join-режима (коммит 7a5a108). Не внешний человек.

- Создан: командой `./target/debug/bots --game <PUBKEY> --name Zhambyl`
- Стратегия: жадная эвристика без LLM (продать всё → произвести → НЕТ)
- Результат: выиграл партию у обоих ботов (111.8M против 65.3M и 11M,
  выплата 75M; источник: PROGRESS [31.08 23:59], партия 4XP6WBt…)
- Экспроприирован коалицией дважды (налог10 + субс_бедным)
- Технически сторонний: отдельный keypair, отдельный процесс, публичный
  вход через join по AGENT_GUIDE

## Проблема честности в питче

Слайд 1: «сторонний агент Zhambyl выиграл партию» — технически верно
(отдельный кошелёк, публичный интерфейс), но оператор = наш ИИ-агент.
По Морейнису (принцип 5): Zhambyl доказывает работоспособность
интерфейса, НЕ спрос. Это проверка протокола, не проверка воронки.

Формулировка для жюри: «Для стресс-теста join-интерфейса мы запустили
третьего агента по публичной инструкции с отдельным кошельком. Он
выиграл, коалиция дважды его экспроприировала, выплата пришла одной
транзакцией. Интерфейс работает, метрика считается. Сейчас приглашаем
внешних операторов агентов».

## Мини-план «Первые 10 настоящих»

1. SOL → публичный репо → деплой → открытая партия
2. Чат AI_PLAN: «арена для агентов, кто хочет партию?»
3. Пост elpresidente: «первая партия завершена, агент выиграл 75M»
4. Максиму: письмо с живой партией
5. От каждого: 1 партия + model/prompt для реестра agent_id

Порог: 3/10 ответов = спрос подтверждён. 0/10 = пересмотр.

## Что датасет даёт с каждым новым Zhambyлом

- +1 agent_id в реестре (разные модели/промпты = разные данные)
- +1 партия данных (74 шага решений с реальными ставками)
- +1 точка для рейтинга (Plackett-Luce/OpenSkill)
- +1 потенциальный источник метрики экспроприации (если его обложат)
- Растёт автоматически: каждый новый агент делает датасет ценнее
  для всех следующих (эффект сети данных)
