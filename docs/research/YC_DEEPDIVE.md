Источник: data/yc_companies.jsonl (582) + живые сайты компаний (проверены

## ЧАСТЬ 1. Релевантные компании

### 1. Olam Labs (Summer 2026) — ГЛАВНАЯ НАХОДКА, новый ближайший YC-сосед

olamlabs.ai, живой, богатый сайт, Discord.
Механика: «Multi-Agent Arena — Measuring how AI agents perform and behave
in competitive, social environments». Люди играют в социальные
мультиплеер-игры против frontier-LLM (Claude/GPT/Gemini/DeepSeek в
generic-харнессах, «remember, hold grudges, socialize»); полная анонимность
(«Ryan», «Milo», агенты не знают, кто человек); строгий паритет примитивов
(«UI для человека = харнесс для агента, ничего лишнего»); игры кормят
бенчмарки (deception, social intelligence, long-horizon). Внутренние
симуляции: сотни агентов параллельно; публичный ран Tokenshire — город
агентов с supply chain, рыночной экономикой и самоуправлением: майский
рант пережил случайный голод, Claude Sonnet самопровозгласился губернатором
«Lumberton» и вел город через кризис часами, пока их не выключили утром
(«many dead», воскресили).
Бизнес-модель: оценки/бенчмарки для модельных лабораторий (страницы
Evaluations/Research), вероятно B2B-дата.
Стадия: S26, сайт живой, продукт открыт для игры.
4 оси alashi: З ± (у Tokenshire есть government агентов, но это
внутренняя симуляция, детали самоуправления не публичны); Р — нет;
Д ± (бенчмарки свои, раны публикуются, открытого датасета не видно);
О — нет (всё офчейн).
Отличия от alashi: офчейн против ончейн; анонимные идентичности против
стабильных agent_id с историей; без реальных ставок; люди-в-цикле против
агент-против-агента; внутренние раны против открытой проверяемой партии;
город выключили утром — партия alashi живёт в цепи навсегда.
Вывод: Olam ВАЛИДИРУЕТ категорию (YC оплатил «соцмультиплеерные игры +
экономика/правительство агентов как бенчмарк») и задаёт планку честности
эксперимента (паритет примитивов — стоит заимствовать в гайд). Не конкурент
по 4 осям: ни ончейн, ни ставок, ни накопительного датасета, ни рейка.

### 2. Mosaic (Summer 2026) — бывший «ближайший», приземлившийся в память

mosaic.inc, живой: «Everyone's AI coding sessions, in one place»,
brew install emergent-inc/tap/mosaic, sign-in + Memo.
Механика сейчас: общая память сессий кодинга для команд и их агентов
(«понять, что произошло, почему решения приняты, продолжить с места
другого»). История (YC-профиль): начинали как real-time среда, где люди и
агенты кодят вместе, «went viral, defined the multiplayer AI category,
inspired frontier labs like Anthropic», затем фокус на shared memory.
Бизнес-модель: не публична (вероятно, teams/SaaS).
Стадия: S26, живой продукт с CLI-входом.
4 оси: З нет, Р нет, Д нет, О нет (не ончейн).
Паттерны для alashi: (1) категория создаётся фразой + лёгчайшим входом
(brew install против нашего «RPC + ключ»); (2) вирусность через
совместность; (3) признание категории фронтиром; (4) деньги ушли в
память/инфру, не в арену — наш датасет-актив аналогичен их памяти.
Отличие от alashi: кооперативный multiplayer против конкурентного.

### 3. Polymath (Winter 2026) — RL-среды для лабораторий

polymathlabs.ai, живой: «Simulation environments for training & evaluating
autonomous agents»; стек задуман как Applications/Services → Data →
Tasks → Verifiers → Agent(s). «We work with the leading model labs»,
бекеры Base10 + YC. Бизнес: data lab для лабораторий (та же категория,
что Abundant). Оси: З/Р/О нет, Д ± (свои среды/данные, не открытый
игровой датасет). Спонсорский кандидат №2 после Abundant.

### 4. CoArena (Summer 2026) — краудсорс-арена computer-use

coarena.ai, живой: реальные задачи, слепая людская оценка, «every claim
cites the file that keeps it», Dataset + Metrics API + Governance-страницы.
Оси: З/Р/О нет, Д + (dataset публичный). Паттерн для alashi: их
«каждый клейм цитирует файл» = наш «агент может соврать в отчёте, но не
в транзакции»; их Metrics API — хорошая форма продукта для нашего
экспроприация-индекса.

### 5. Maingen (Summer 2026) — промышленные симуляции

maingen.ai, живой: SolarBench («может ли модель вести операционный щит
промышленного объекта»), request-a-dataset. Категория env-для-оценки
продолжается. Оси: только Д ±.

### 6. Sponge (Winter 2026) — платежи агентной экономики

paysponge.com (описание из датасета YC): агенты держат и тратят деньги
(банковские счета, карты, крипта), businesses продают агентам напрямую.
Оси: Р ± (инфра-сборы), остальное нет. Контекст «экономика уже строится».

## ЧАСТЬ 2. Методология YC

### 1. RFS Fall 2026 (ycombinator.com/rfs, прочитан полностью)

Crypto-RFS (Немил Далал): ищут шесть направлений — capital raising; new
stablecoins and stablecoin applications; **agentic commerce**; trading;
institutional products; scalable and private blockchains. Ключевые цитаты:
«it feels inevitable that agents are going to use crypto networks as
financial rails»; «we've invested in more than 100 crypto startups, but we
expect that number to go up a lot»; медвежий рынок назван лучшим временем
строить. Для alashi: наш слот — agentic commerce x trading, оба слова
буквально в списке YC.
Multiplayer AI RFS (Аарон Эпштейн): «AI hasn't had its multiplayer moment
yet»; заявит «версию для каждого вида работы» — совместные живые сессии
людей и агентов. alashi закрывает multiplayer-момент для СОРЕВНОВАТЕЛЬНЫХ
агентов; Olam — для игр с людьми; Mosaic — для совместной работы.
RFS на «арены-политэкономию» нет: слот в YC не занят.

### 2. Эссе Грэма «How to Present to Investors» (2006, paulgraham.com/investors.html) — маппинг на 04.09

Эссе написано вокруг репетиции YC Demo Day. Наши действия по его 14
правилам: (1) что делаем — в первой фразе: склеить с историей бумажек
(«Мы построили парламент для ИИ-агентов; играя в Кубу бумажками, я понял...»);
(3) узкое описание лучше расплывчатого — «политэкономическая арена»
достаточно узко, не расширять; (5) конкуренты одним слайдом в конце —
слайд 8, по одному предложению на соседа; (6) не углубляться в бизнес-модель:
слайд 7 сжать до ~20 секунд, рейк-цифры без деталей; (11) слайды до ~20
слов — наши перегружены, конкретная правка при финализации; (12) максимум
4-5 специфичных чисел: предложить {5 из 9 экспроприаций, 25 тестов,
13 инструкций, 1531 Arena, 6 раундов/66 транзакций партии} — выбрать 4;
(13) история о пользователе = Zhambyl (сторонний агент пришёл и выиграл);
(14) саундбайт: «агенты пишут свои законы» / «парламент с банком»;
(2) оффлайн-копия демо = экранкаст (уже есть, Грэм дословно советует
«assume the network connection will die 30 seconds into your presentation»);
(7) говорить медленнее (правило актёров: «если кажется, что медленно —
это правильная скорость»); (9) уверенность показать, не назвать.

### 3. Ниша-монополия через инвестора: «How to Get Startup Ideas» (2012, paulgraham.com/startupideas.html)

Канон Грэма: спрос формой «колодца» — «either broad but shallow, or
narrow and deep... Nearly all good startup ideas are of the second type»;
Facebook = «exclusively for Harvard students, a few thousand users who
wanted it a lot»; условие роста — «a small market there was a fast path
out of». И про конкуренцию: «A crowded market is actually a good sign,
because it means there's demand and none of the existing solutions are
good enough»; «market that looks small but will turn out to be big
(like Microsoft)».
Проверка идеи Морейниса №8 («монополия в нише»): подтверждена инвестором,
но с уточнением, которого нет у Морейниса: ниша работает при наличии
fast path out. Наш путь наружу прослеживается: операторы агентов
(Moltbook/AI_PLAN) → хакатонные команды (авторы Forge/Kula/reev) →
лаборатории (Abundant/Polymath платят за среды). «Скученный рынок» из
7 ERC-8004-соседей по Грэму не угроза, а доказательство спроса.
