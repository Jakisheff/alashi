# agent-context-ab (15.11.2026)

Вопрос: меняет ли компактный процедурный контекст (рука skill) поведение агента
против документации (quickstart) и отсутствия добавки (naked), в парах по сиду.

## Дизайн

- 36 сидов × 3 руки × 1 место (seat 0), соперники greedy+tactical, epoch 1,
  vote_weight_mode 1. Движок `bin/evalgame` (мост сырых действий, текущий
  main, sha в protocol.json), glm-5.3, executor settings заморожены в
  protocol.json. Протокол: агент возвращает `{"action": ...}`; невалидная
  схема → parse_error + fallback pass; законное по схеме, но невозможное
  действие → ход сгорает (ok=false).
- Руки отличаются только memory.md, добавляемым в системный промпт:
  naked — пусто; quickstart — docs/QUICKSTART_JURY.md дословно;
  skill — процедура с числами из разборов партий (inbox/Agent3, 02.09).
- Воспроизведение: `python3 make_protocol.py && python3 collect.py &&
  python3 analysis.py && python3 ../../../tools/eval_report.py .`

## Результаты (108/108 игр, 0 провалов, 36 кластеров)

| рука | выплата | rank | wealth_first | лицензия | игры с parse-ошибкой | illegal | ток/игра |

| naked | 49.89M | 1.64 | 0.61 | 0.83 | 16/36 | 3/36 | 53k |

- Выплата: значимых различий нет. skill−naked −0.78M (SD 20.2, p=0.292,
  CI [−7.2, +6.1]); quickstart−naked +0.48M (p=0.851).
- Протокольные ошибки формата: skill−naked McNemar exact p=0.035
  (решающих игр 3 против 12); quickstart−naked p=0.581. Процедура режет
  ошибки формата, документация — нет.
- Illegal-действия: skill 6/36 против naked 3/36, p=0.508 (не значимо;
  процедура провоцирует больше попыток взяток/ставок).
- Ограничение мощности: фактический SD парных разностей 20.2M против
  планируемого 8.2M (интерфейс сырых действий шумнее меню кандидатов);
  MDE по выплате 9.45M при 36 сидах.

## Интерпретация и границы

Паттерн совпадает с литературой (Vercel: документация не активируется,
процедуры работают): процедурный контекст значимо снижает ошибки
протокола, не меняя выплату на этой задаче. Абсолютные числа привязаны
к движку commit 095f0e0 и интерфейсу сырых действий; перенос на HTTP-арену
проверяется отдельным слепым прогоном (см. PROGRESS 15.11).

Сырье: runs/ (трассы, game.json), game-calls/ (2428 пар запрос-ответ,
токены в usage), protocol.json (хэши всех компонентов и рук).

## Clean-room HTTP-прогон (слепые агенты против живого arenad)

cleanroom/driver.py: три изолированные арены (порты 8150+), логирующий
прокси (HTTP-статус + ok:false тела), соперники --no-llm, слепой агент
arena/target/release/agent --model glm-5.3 через loopback-llm-shim
(ALASHI_TEST_MOCK_LLM_BASE, ключ кодинг-плана; бинарник не менялся).
Прогон 15.11: LLM работал (36.9k/64.3k/62.8k токенов на агента,
111 вызовов), все три партии завершены.

| рука | запросов | HTTP 4xx | отказы арены (ok:false) | вид |
|---|---|---|---|---|
| naked | 1168 | 0 | 3 | все storage_failed (инфраструктура) |
| quickstart | 1165 | 0 | 1 | storage_failed |
| skill | 1111 | 0 | 4 | 2 bad_params + 2 WrongPhase (протокол) |

Вывод (пилот, n=1 на руку): обёртка-бинарник устраняет ошибки формата
целиком (0 HTTP 4xx при живом LLM); процедурный файл поверх встроенного
протокола клиента может ВНОСить фазовые/параметрические ошибки — тот же
паттерн, что illegal-действия в основной серии. Сырьё: proxy-*.jsonl,
agent-*.log, llm-shim-8190.jsonl, summary.json.
