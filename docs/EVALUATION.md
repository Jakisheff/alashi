# Сравнение версий агента

source_defined: инструмент запускает локальные партии Alashi через текущий `rules::sim::Simulator`. Один вариант агента заменяется другим при сохранении условий. Правила игры остаются прежними.

## Как запустить сравнение

Из корня репозитория:

```sh
cargo build --offline --manifest-path arena/Cargo.toml --bin evalgame
python3 tools/compare_agents.py --config data/eval/configs/builtin.json --out data/eval/runs/builtin-01
```

Каталог результата должен быть новым. Повтор команды с тем же `--out` завершается ошибкой, чтобы не затереть предыдущий эксперимент.

`builtin.json` сравнивает greedy с tactical. Это проверка инструмента на эвристиках. Для двух версий внешнего агента есть пример:

```sh
python3 tools/compare_agents.py --config data/eval/configs/external.json --out data/eval/runs/external-01
```

В нём меняется ставка Python-агента: 4 или 8 игровых песо. Модель не вызывается. Для своего агента замените `command` в конфигурации и перечислите код агента и файлы промпта в `artifacts`. Для скомпилированного агента укажите также его исполняемый файл.

## Условия сравнения

source_defined: каждый seed проходит все позиции испытуемого за столом. Порядок A/B чередуется. Соперники сохраняют свои генераторы случайности при ротации посадки. Обе версии получают одинаковые начальные условия; последующие состояния зависят от их действий.

Основной результат: выплата B минус выплата A. Отдельно сохраняется ранг по правилам распределения банка. Он может отличаться от порядка итоговых выплат с учётом ренты.

Интервал строится bootstrap-перевыборкой средних по seed, а не отдельных зависимых позиций. Seed с незавершённой позицией не входит в среднее полных групп. При этом все ошибки и завершённые пары остаются в отчёте. При одной полной группе интервал не вычисляется.

hypothesis: выбранный набор seed и соперников представляет интересующие пользователя условия. Маленькая фиксированная выборка не доказывает перенос результата на других соперников. Нельзя многократно подбирать варианты по одной серии и затем называть эту же серию независимой проверкой.

## Внешний агент

`command` задаётся массивом аргументов. Shell не используется. Рабочая папка процесса совпадает с корнем репозитория. Адаптер исполняется с обычными правами пользователя, без изоляции файловой системы; запускайте собственный проверенный код.

На каждое решение запускается новый процесс. Он получает один JSON через stdin и возвращает один JSON через stdout. Локальная память процесса не сохраняется. История собственных наблюдений и ответов передаётся в `history`; история начинается заново для каждой партии.

Запрос версии 2 содержит `schema_version`, `match_id`, `decision_index`, `phase`, `rules`, `observation` и `history`. `match_id` является случайным UUID, постоянным внутри одного запуска партии и независимым от seed. При повторе партии создаётся новый ID. Поле `game_seed` удалено: адаптеры с проверкой версии 1 нужно обновить. Версия конфигурации остаётся 1.

source_defined: seed сохраняется в результатах harness для повторного расчёта, но не передаётся в запросе адаптеру. Это закрывает прямой канал раскрытия seed в JSON. Локальный адаптер по-прежнему работает без изоляции и может читать доступные пользователю файлы, включая конфигурацию с seed и результаты предыдущих партий. Протокол не обеспечивает секретность против такого адаптера; перед недоверенным соревнованием нужна отдельная изоляция. HMAC со скрытым ключом также требует защиты ключа от адаптера.

Канал восстановления seed из наблюдений измерен на записанном прогоне external-20260907. Вся случайность партии выводится из одной величины публичными формулами (arena/src/runner.rs, rules/src/transitions.rs). Шесть карт законов, доступных в наблюдениях, сузили диапазон `0..10 000 000` до 107-5529 кандидатов; истинный seed присутствовал в каждом списке. Доказательство оформлено тестом tools/test_seed_inference.py. Поэтому сравнения для внешних операторов запускаются с `"seeds": "auto"`: harness генерирует непредсказуемые u64 из ОС в момент прогона (необязательное поле `auto_seed_count`, по умолчанию 3) и записывает конкретный список в config.json прогона; пример external.json переведён на этот режим. Короткие человеческие seed допустимы только во внутренних тестах. Восстановление криптографического seed перебором наблюдений одной партии не показано и считается закрытым по числу доступных ограничений; чтение файлов недоверенным адаптером остаётся открытым до изоляции.

Поля observation соответствуют `Obs` симулятора: видимые остатки и влияние по фракциям, состояние цены, карта закона и президент. Это проекция встроенного интерфейса стратегий; она не содержит всех полей HTTP API эпохи 90-х. В частности, интерфейс не предоставляет отдельные балансы валюты и векселей. Сравнение относится к агентам с этой проекцией наблюдения.

source_defined: наблюдение дополнено vote_weight_mode, массивами acted_stamp и vote_weight, признаками voted и veto_pending. В Law vote_weight совпадает с весом при подсчёте для участвующих фракций; вне Law он предварительный. Поле decision_stage равно primary до голоса и post_vote при дополнительном запросе после него. Поле voted индексируется так же, как cash.

source_defined: после голосования runner даёт одно дополнительное решение каждой живой проголосовавшей фракции, пока вето не применено. Ответ для post_vote: veto или pass. Повторный голос будет отклонён движком и останется в журнале. Встроенные стратегии по умолчанию пропускают это решение; внешний пример обновлён. Адаптерам нужно обработать post_vote, иначе прежний ответ vote_yes приведёт к AlreadyVoted. Дополнительный вызов учитывается в стоимости и времени партии. Версия JSON-запроса остаётся 2, поля добавлены к observation.

Ответы по фазам:

| Фаза | action | Дополнительные поля |
| --- | --- | --- |
| market | sell, buy, sell_credit | units |
| market | pass | нет |
| action | produce, donkey, shuttle, pass | нет |
| action | bribe | to, amount |
| action | roof | to, tariff |
| action | bid | amount |
| law | vote_yes, vote_no, vote_abstain, veto, pass | нет |

Денежные значения передаются в минимальных единицах: 1 игровой песо = 1 000 000. `to` является индексом фракции. Корректный JSON ещё не означает допустимый ход: окончательное решение принимает движок правил.

Необязательное `cost_usd` содержит заявленную адаптером стоимость вызова. Отсутствующее значение остаётся неизвестным. `source: "fallback"` позволяет адаптеру явно объявить собственную подстановку. Название модели и стоимость не удостоверяются провайдером.

source_defined: таймаут, аварийный выход или некорректный ответ заменяются явным `pass` и записываются как fallback. Отказ правил сохраняется отдельно. Python-обвязка ограничивает время вызова; общий лимит партии не превышает 60 секунд. Если ответ после исполнения потерян, адаптер сам отвечает за идемпотентность своих внешних действий.

Виртуальные часы симулятора не учитывают физическую задержку выбора хода. Длительность вызовов измеряется, но её влияние на очередность живой арены этим экспериментом не проверяется.

## Результаты и происхождение

Откройте `report.html` в каталоге результата. Отчёт показывает парные выплаты и первое различие действий. Ошибки вызовов отделены от отказов правил.

`evidence.json` содержит эпизоды с указателями на исходную партию. После принятого закона записывается следующее наблюдение агента вместе с решением. Это материал для анализа адаптации, не готовый балл адаптивности. Контрфактические выплаты не выдумываются.

В `cases` остаются исходные партии и полные трассы наблюдений. Ошибочные запуски также сохраняются. `manifest.json` фиксирует условия и хэши артефактов; `source.zip` сохраняет исходники движка вместе с явно указанными файлами агента. Секреты в `artifacts` или аргументах команд добавлять нельзя. Окружение процесса в манифест не копируется.

Проверка сохранённых файлов:

```sh
python3 tools/compare_agents.py --verify data/eval/runs/external-01
```

Хэши позволяют обнаружить изменения относительно манифеста. Они не доказывают идентичность модели или независимость оператора. Для повторения внешнего вызова нужны также та же среда исполнения и доступная версия провайдера; одинаковый seed не делает облачную модель детерминированной.

## Пилот с операторами

hypothesis: пять подходящих операторов из одного сообщества. Предложение: сравнить две версии агента и разобрать полученные различия решений. Контакты не отправлены; пользователи и оплаты не заявлены.

target: лимит планирования 11 часов работы организатора. Из них 6 часов на подготовку протокола, поиск участников и общий итог. Ещё по часу на оператора для подключения и разбора. Это бюджет времени, а не измеренный факт. Дополнительная интеграция потребует пересмотра лимита.

target: календарное окно 14 дней после первого приглашения. Ответы людей не гарантированы. По окончании окна фиксируются все обращения и исходы, даже если когорта не набрана. Сам по себе отказ или отсутствие ответа не доказывает отсутствия спроса.

Смета хранится в `data/eval/configs/pilot_budget.json`:

```sh
python3 tools/pilot_budget.py data/eval/configs/pilot_budget.json
```

Стоимость часа пока неизвестна. Бюджет модельных вызовов и прочие расходы также не измерены. Калькулятор сохраняет неизвестные значения как `null`. Перед приглашениями нужно заполнить их и определить цену предложения в одной валюте. Цена безубыточности при оплате всеми участниками не является доказанной готовностью платить.

Формула бюджета: 11 часов × внутренняя стоимость часа + 5 × лимит инференса на оператора + прочие расходы. Цена предложения хранится отдельно; калькулятор показывает результат при оплате всеми пятью участниками. Бесплатный пилот обозначается ценой 0 и проверяет использование, без вывода об оплате.

`pilot_ledger.csv` создаётся пустым при каждом эксперименте. В нём отдельно учитываются прежний способ проверки и потраченное время. Дальнейшие поля фиксируют подключение и полезность результата. Платёж учитывается отдельно от повторного участия. Заполненный журнал является новым артефактом; сохраните его отдельно от исходного пакета сравнения, если хотите сохранить проверку первоначальных хэшей.

not_validated: полезность для внешнего разработчика, фактическая цена и срок его подключения. Локальный результат не заполняет эти поля автоматически.

## Эволюционная лестница соперников (genome)

`GenomeBot` в `arena/src/strategies.rs` управляется шестью параметрами вместо зашитых констант: порог дна цены для закупки, резерв кэша, лимит единиц закупки, аппетит взяток, порог кэша для взятки и ставка на лицензию. Границы генов заданы в `GENE_MIN`/`GENE_MAX`; геном сериализуется в JSON.

`arena/src/bin/evoagents.rs` калибрует уровни силы. Для каждой цели в миллионах песо выплаты эволюция подгоняет геном под цель (фитнес −|выплата − цель|), финальный уровень максимизирует выплату. Все геномы поколения играют одно расписание seed×seat против одного микса соперников, поэтому их оценки сравнимы между собой. В артефакт входит парная проверка соседних уровней на свежих сидах с зеркальными местами.

```sh
cargo run --manifest-path arena/Cargo.toml --bin evoagents -- \
    --out data/eval/evolved/ladder.json
```

Артефакт 28.09: `data/eval/evolved/ladder-20260928.json`. Цели 6/10/14/18M и максимум достигнуты как 5,94/9,98/13,89/17,81/23,75M; парная проверка на 40 зеркальных парах дала +3,62/+6,23/+1,31/+6,12 млн песо в пользу более позднего уровня.

Имя `genome` принимается везде, где ранее работали встроенные имена ботов, и доступно как соперник или вариант в сравнении агентов; без явного генома оно эквивалентно tactical. Подключение конкретных геномов уровней как соперников в конфиг сравнения остаётся следующим шагом.

not_validated: сила уровня гарантирована только относительно микса greedy/tactical/greedy/random на использованном расписании сидов. Перенос на другие миксы и на живых внешних агентов не измерялся.

## Основания

[AB_LICENSE_RENT](research/AB_LICENSE_RENT.md) сравнивает правило расчёта ренты. Из него использован принцип контролируемого сравнения, а не доказательство пользы сравнения промптов.

[Разбор Морейниса](research/MOREINIS_REVIEW_20260906.md) предлагает пилот с двумя версиями агента. Реализация этого инструмента не превращает предложенный пилот в проведённый.
