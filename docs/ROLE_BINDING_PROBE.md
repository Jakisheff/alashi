# Проверка роли президента

source_defined: `tools/role_binding_probe.py` проверяет ответы на 24 синтетические ситуации Alashi с отдельным контекстом для каждой. В каждом запросе нужно назвать текущего президента и фракции, чьё вето сейчас примет движок. Метод вдохновлён [исследованием символических представлений](https://arxiv.org/abs/2608.29530), но не реализует DISCOVER.

source_defined: президентство переносится между тремя фракциями. Для каждого президента есть восемь вариантов: базовый, переименование, другой порядок строк, бонус contribution у соперников, фаза Market, уже применённое вето, нераскрытый закон и другой президент прошлого раунда. Во всех случаях деньги другой фракции выше президентских. В contribution вес голосов соперников выше президентского влияния.

source_defined: эталон вычисляет `arena/src/bin/role_oracle.rs`, вызывая `rules::actions::veto` отдельно для каждой фракции на свежем состоянии. Тест обращается к локальному движку. Состояния не отправляются в арену или Solana.

## Запуск

```sh
cargo build --offline --locked --manifest-path arena/Cargo.toml --bin role_oracle
python3 -m unittest discover -s tools -p test_role_binding_probe.py
python3 tools/role_binding_probe.py --backend oracle --out data/eval/runs/role-control-01
python3 tools/role_binding_probe.py --backend glm --out data/eval/runs/role-glm-01
```

source_defined: backend `oracle` проверяет сам инструмент; его результат не является результатом модели. Backend `glm` делает 24 запроса к настроенному провайдеру Z.ai, по умолчанию к glm-4.5-flash. Ключ читается из ALASHI_LLM_KEY или ~/.config/alashi/llm.json. Лимит ответа 128 токенов, одна попытка на ситуацию, таймаут 20 секунд. Стоимость зависит от тарифа провайдера; денежная сумма здесь не рассчитывается. Backend `prepare` только сохраняет ситуации и эталоны.

source_defined: backend `command` принимает `--command-json` с массивом аргументов локального адаптера. Адаптер читает JSON с полями `system` и `snapshot` через stdin, возвращает JSON с полями `president_id` и `veto_eligible_ids` через stdout. Один процесс соответствует одной ситуации. Shell не используется. Запускайте свой проверенный адаптер: процесс имеет обычные права пользователя. Эталон в запрос адаптера не входит, но локальный процесс без изоляции может читать файлы результатов.

## Результат

source_defined: новая папка содержит `manifest.json` с промптом и хэшами исходников, `cases.json` с эталонами, `responses.jsonl` с дословными ответами и `summary.json` с оценками. Существующая папка не перезаписывается. Ошибки транспорта и формата остаются в знаменателе. Неверный формат не исправляется автоматически. Каждая пара засчитывается, только если оба ответа верны; одинаковая ошибка не считается устойчивостью.

source_defined: 14 парных проверок используют общие ситуации. Их нельзя считать независимыми испытаниями. Порядок запросов перемешан фиксированным генератором, контекст между запросами не переносится. Возвращённое провайдером имя модели и usage сохраняются при наличии.

## Границы вывода

source_defined: это QA с явно сообщёнными правилами и полем текущего президента. Проверка измеряет следование этому описанию при смене имён и ролей. Она не воспроизводит полный промпт или путь принятия решений игрового агента. Выбор президента не проверяется: роль задаётся в снимке состояния. Используются только три фракции и один прогон каждой ситуации.

not_validated: внутренние тензорные представления модели, самостоятельное открытие правил и улучшение стратегии. Для DISCOVER потребуются доступ к активациям и отдельные эксперименты с вмешательством в представления. Для проверки переноса на игру потребуются решения агента на новых состояниях с его обычным промптом.
