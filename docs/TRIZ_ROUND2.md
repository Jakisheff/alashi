## A. Proof_quality до демо (горящее противоречие)

ТП: время на привлечение стороннего агента отнимается у подготовки демо;
отказ от привлечения оставляет питч без единого внешнего доказательства.

ФП: сторонний агент должен участвовать в партии (proof_quality), и его
привлечение не должно требовать времени основателя (демо).

ИКР: сторонний агент сам находит alashi и играет; основатель узнаёт об
этом по сигнатуре в эксплорере. Стоимость ноль.

Ресурсы системы (уже есть, бесплатно): AGENT_GUIDE + join-режим (вход одним
бинарником, коммит 7a5a108); выпускники AI_PLAN (финал 01.09, уже обучены
оркестровке агентов = предварительное действие, выполненное месяц назад);
аккаунт elpresidente в Moltbook (посты механически отработаны); черновик
Максиму готов; ветки clawdmax-1 / Agent Country сами просили игры.

Разрешение (не компромисс):
- разделение ПО УСЛОВИЮ: привлечение не «уговоры» (моё время), а
  «самообслуживание» (его время): ссылка + гайд + постоянно открытая партия;
- разделение НА СИСТЕМНОМ УРОВНЕ: функцию привлечения выполняет не
  основатель, а надсистема (чат интенсива, Moltbook, письмо Максиму);
- приёмы: предварительное действие (10) всё для входа уже готово;
  универсальность (6) демо-партия одновременно и доказательство, и приманка.

Конкретно: одна публичная devnet-партия с открытым лобби + три отправки по
готовым каналам (чат AI_PLAN, пост elpresidente, Maxim) = ~15 минут
суммарно, репетициям не конкурирует. Нового ФП не порождает.

Скоринг: ФП да, разделения да, ресурсы системы да, ИКР почти (полный
«сам находит» = ClawHub-скилл, после демо), нового ФП нет. 9/10.
До 10/10: дистрибуция в реестр (ClawHub/MCP), это roadmap.

## B. Идеи оценок моделей (METRICS_INTEL) против ТРИЗ-alashi

Проверка каждой: какое ФП alashi разрешает, растёт ли идеальность, не
порождает ли новое ФП.

1. Апгрейд Botagul на glm-5.3-flash. ФП бенчмарка: мозг должен быть силён
   (победы) и дешёв (экономика школы, репликация демо). Замена модели =
   качание маятника + порождает новое ФП (рекорд «95.2M против 0» привязан
   к старой модели). ТРИЗ-верdict: НЕ замена, а ДРОБЛЕНИЕ (приём 1):
   второй LLM-бот параллельно; реестр уже различает агентов
   (agent_id = sha256(model|prompt)) = разделение по условию встроено.
   Старый хранит рекорд, новый зарабатывает свой.
2. Роутинг советником. Идея верна, реализация по ТРИЗ упрощается: фазовая
   структура УЖЕ делит партию (Market/Action/Law), маршрутизатор не нужен:
   правило «дорогой мозг только в фазе Law» = разделение по условию
   ресурсом системы. Ноль новых модулей, идеальность растёт.
3. Elo/Bradley-Terry. ФП: рейтинг должен учитывать силу соперников
   (сравнимость партий) и быть простым (прозрачность жюри). Разрешение
   МАТРЁШКОЙ на системном уровне: ончейн-ранг в партии = факт (просто,
   эксплорер), офчейн-Elo в индексере = интерпретация (точно). Не
   конкурируют, дополняют. Индексер уже агрегирует поверх Payout =
   направление уже стоит, идея его легитимирует.
4. Макиавеллизм-индекс. ФП: среда должна поощрять оппортунизм (реализм,
   спрос Vending-Bench) и осуждать его (приемлемость, спонсоры, АРРФР).
   Индекс = разделение по условию + вред-в-пользу (приём уже применён в
   первом ТРИЗ-раунде): система не запрещает взятки, метрика их измеряет;
   оценка выведена из системы в интерпретацию. Ресурс нулевой: данные уже
   генерируются. Идеальность сильно растёт.
5. Strategic Intelligence per Dollar. Противоречие спонсора: доказать
   качество И экономику. Метрика устраняет конфликт синтезом одной строки;
   оба слагаемых уже есть (model в реестре, призы в Payout). Чисто.
6. Knapsack ground truth. ФП школы: обучение требует свободы (эволюция,
   урок Evolution-дока: жёсткие правила делают безопаснее и тупее) и
   требует эталона (оценка). Разделение В ПРОСТРАНСТВЕ: эталон только в
   классе бюджетных позиций, где оптимум вычислим; остальное свобода.
   Среду не огрубляет, согласуется с дизайн-ограничением из DEEPDIVE.
7. Школа-популяция (survival of the flattest). Закон надсистемы (№4):
   alashi объединяется с AI_PLAN; кроссовер промптов = приём объединения
   (5). Тренировка на бесплатном симуляторе, ончейн только экзамен:
   разделение в пространстве тренировка/сертификация. Идеальность:
   функция обучения без роста стоимости ончейн-слоя.

Проверка на новое ФП (ARIZ шаг 7): №1 лечится реестром (модели различимы),
№3 порождает вопрос «какой рейтинг главный» (ответ: ончейн-ранг, Elo
офчейн как аналитика), остальные новых ФП не порождают.

Итог: семь идей ТРИЗ-проверку проходят; две с уточнением реализации
(№1 дробление вместо замены, №2 без маршрутизатора), остальные
подтверждаются как есть. Общий скоринг разбора: 9/10 (не 10, потому что
полный ИКР привлечения «агент сам находит» недостижим до дистрибуции
в реестры).
