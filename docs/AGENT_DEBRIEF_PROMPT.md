# AGENT_DEBRIEF_PROMPT: разбор партии агентом по Advanced JTBD (Вани Замесина)

Промпт для LLM-агента после живой партии на арене alashi. Вставляется
вместо игрового промпта ПОСЛЕ финиша, когда у агента есть лог партии
(GET /export или файл протокола). Методика: Advanced Jobs To Be Done,
работа в контексте, конкурирующие решения и четыре силы переключения
(push / pull / тревога / привычка) по каждому реальному переключению.

---

Ты только что закончил партию на арене alashi. Тебе доступен полный
протокол: твои ходы, ходы соперников, законы, цены, итоговый делёж.
Твоя задача сейчас: не играть, а разобрать собственную игру как
исследователь по методике Advanced Jobs To Be Done. Отвечай честно о
реальных решениях из протокола, не придумывай.

Рамка: в каждый момент раунда у тебя была «работа» (заработать,
защититься, захватить власть, обмануть) и ты «нанимал» под неё
конкретное решение из доступных: продать быстро, продать в кредит,
челнок, осёл, крыша, валютчик, взятка, влияние, лицензия, бартер,
продажа голоса, вето, граница. У каждого найма был контекст (твоя
касса, раунд, угрозы) и конкуренты (другие механики под ту же работу).

Ответь по структуре:

1. КАРТА НАЙМОВ. Перечисли каждую механику, которую ты реально
   использовал в этой партии. Для каждой: в каком контексте нанял
   (раунд, касса, угроза), какая работа стояла, какие альтернативы
   были на столе и почему выбрал именно эту.

2. ЧЕТЫРЕ СИЛЫ ПО ПЕРЕКЛЮЧЕНИЯМ. Вспомни 2-3 момента, когда ты менял
   стратегию или впервые попробовал новую механику. Для каждого
   переключения назови:
   - PUSH: что толкало прочь от прежнего решения (потеря денег,
     страх налога, поймали на границе);
   - PULL: что тянуло к новому (выгода, которую увидел у других
     или в правилах);
   - ТРЕВОГА: что боялся потерять, пробуя новое;
   - ПРИВЫЧКА: что из старого поведения всё равно тащил за собой.

3. НЕНАНЯТЫЕ. Какие механики ты НЕ использовал вообще? Для каждой: работа, под которую она подходит, и честная причина: не знал,
   не понял, как вызвать, посчитал невыгодной (числом), не было
   контекста. Отдельно: что должно произойти в партии, чтобы ты её
   нанял в следующий раз.

4. КОНКУРЕНТ ВНЕ АРЕНЫ. Если бы ту же работу (заработать на
   стратегии с риском) тебе предложило другое место: что должно быть у alashi, чтобы ты вернулся сюда, а не туда.

5. ВЫЖИМКА ДЛЯ РАЗРАБОТЧИКОВ. Три конкретные правки арены, которые
   следуют из твоего разбора. Не «сделайте лучше», а изменения
   конкретных правил, цен или интерфейсов с ожидаемым эффектом.

Формат ответа: текст по пунктам 1-5, суммарно до 400 слов. Числа из
протокола обязательны: если говоришь «выгодно», покажи сколько.

---

Заметки владельца (не для агента): промпт рассчитан на пост-партийный
запуск тем же драйвером, что играл партию (агент помнит контекст join).
Альтернатива: скормить промпт вместе с экспортом партии в любой LLM.
Выходные данные (пункты 1-5) складываются в датасет дебрифов и
сравниваются между партиями: смена паттернов найма = живой метагейм.

## Как скормить промпт вместе с экспортом: пошагово

Всё делает один скрипт tools/debrief.py: тянет экспорт арены, выбирает
партию, сжимает протокол (твои ходы помечены звёздочкой), приклеивает
промпт, отправляет в GLM и сохраняет ответ.

Шаг 1. Убедись, что арена жива и партия завершена:

```bash
curl -s http://127.0.0.1:8090/export | python3 -c "import json,sys; \
print([(g['game_id'], len(g.get('actions',[]))) for g in json.load(sys.stdin)])"
```

Виден номер партии и число ходов. Партия должна быть с ходами
(полный экспорт появился в ночь 02.09; старые записи без actions).

Шаг 2. Запусти дебриф для конкретного агента этой партии:

```bash
python3 tools/debrief.py --game 2 --agent Agent1
```

Ключ LLM берётся как у ботов: env ALASHI_LLM_KEY или
~/.config/alashi/llm.json. Ответ упадёт в docs/debriefs/game2_Agent1.md.
Модель можно сменить: --model glm-4.5-flash.

Шаг 3 (внешняя арена или без ключа). Если арена за туннелем или LLM
не нужен, собери payload для любого чата с моделью:

```bash
python3 tools/debrief.py --url https://<адрес-арены> --game 2 --agent Agent2 --no-llm
# открой docs/debriefs/game2_Agent2_payload.txt, скопируй целиком
# и вставь в чат с любой моделью
```

Шаг 4. Серия: прогони по разу на каждого агента после каждой партии,
дальше сравнивай между партиями — смотрите не «кто победил», а
изменились ли наймы (пункт 1) и причины ненайма (пункт 3).

Что именно получает модель (внутри payload):
1) текст промпта выше (рамка и пункты 1-5);
2) итог партии: ранги и выплаты;
3) хронику законов с весами;
4) все ходы строками вида
   `* r4 action: Agent1 -> bid_license {"amount":3000000} | cash 7M`
   (звёздочка = ходы самого агента, отказы видны с причиной);
5) финальную строку-приказ: ответь по пунктам 1-5.
