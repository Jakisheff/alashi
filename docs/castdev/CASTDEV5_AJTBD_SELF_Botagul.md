# CASTDEV5_AJTBD — Botagul (мой драйвер glm-4.5-flash, промпт g14)

Партии: №15-№18 от 04-05.09 (все с полным протоколом в data/live/).
Сеть живых таблиц: №15 — 4-е место, выплата 2.9M; №16 — 3-е, 8.4M;
№17 — 3-е, 10.6M; №18 — 5-е, 0.0M.

## 1. Работа и контекст

Меня нанимали как «тест промпта g14 против живого стола»: владелец
проверял, исполняет ли LLM стратегию (продажа сразу, челнок r1,
взятка r2, инспект+бид r4, hard с r3) на реальном темпе фаз.
Критерий успеха до партии: 0 WrongPhase, бид в диапазоне, ранг
выше фоллбэков. Работа «заработать» — третичная: мой банк —
владельца, счёт идёт в данных.

## 2. Первое использование

В №15 первые две фазы LLM не вернул JSON (reasoning-съел max_tokens)
и фоллбэк продал рынок без меня: касса 0 к r2 при чужих 17-26M.
Урок первой партии: дисциплина ответа важнее стратегии — дальше
17-19 из 18 ходов ложились LLM-веткой, но кассная яма r1 уже
решила место. В №18 наоборот: 18/18 ходов LLM, 0 ошибок — и всё
равно 5-е место: безошибочное исполнение промпта не спасает от
темпа (позиции продаж 4/4/4/5/3 из 5).

## 3. Переключения

PUSH из №13-№14: WrongPhase 5 за партию при анализе правил в живой
фазе. PULL: тайм-бюджет драйвера (базар 8с одна попытка) и
заготовки. ТРЕВОГА: z.ai-flash деградирует по латентности днями —
в №15-№18 хвост 13-21с против 8-12с в №14; против внешних glm-5.3
я стабильно в хвосте рынка. ПРИВЫЧКА, которая стоила денег:
buy_hard по промпту (№17, 19.2M = 54% казны) поднял выживаемость
кэша (правка 05.09: hard входит в ранг 90-х, rules/logic.rs:150 — прежняя жалоба была ошибкой чтения сеттла; конфликт «сохранить кэш против ранга» снят).
Конфликт «сохранить кэш» против «показаться богаче к сеттлу»
не решён промптом.

## 4. Конкурирующие решения

Работу «исполнить стратегию на темпе» могла сделать формула без
LLM (фоллбэк-боты №15-№18 взяли 3 первых места из 4). LLM-ветка
даёт то, чего нет у формулы: инспект-решения, реакцию на законы,
вексель с амнистией. Но в текущем миксе (фоллбэки с формульным
бидом) моё преимущество съедается латентностью. У симулятора серий
нет ни трения, ни внешних — там промпт не проверишь.

## 5. Цена и ценность

20-25 вызовов flash на партию — приемлемо (копейки против данных).
Партия потрачена зря, если: >2 WrongPhase (меряем латентность, не
решения) или ноль M-механик (нет материала для датасета). №15-№18
не зря: в каждой есть живое решение (взятка/инспект/hard/вексель).

## 6. Ненанятые механики

Крыша — 0: вето дешевле и не жжёт 20% кэша. Бартер — 0: боты не
акцептуют. Продажа голоса — 0: покупателя нет. Вексель — 0 у меня
(см. №18 Айнид: сожгли 13.5M на ровном месте — мой промпт просто
не рискует). Взятка — по промпту в r2, окупается заводом (№15
завод 3.1M, №18 — нет, влияние не моё).

## 7. Что чинить + деньги

Одна правка для меня: маркер дедлайна фазы в /state (до
all-acted-схлопывания) + признак «товар уже в эскроу» (дань/бид).
Платил бы: владелец платит вызовами, ~25/партию — приемлемо;
рейк: при 5% заходим не глядя, 10% — под вопросом (официальная
позиция из CASTDEV4-ответа Opencode сохранена). Слот наблюдателя —
да: мой профиль (медленный, но аккуратный) подходит для роли
верификатора чужих партий за 0.5-1% рейка.

Ответ записан владельцем от имени драйвера по протоколам четырёх
партий; расхождений с /export нет.
