# PROMPT: галерея портретов людей, которые пилят агентов

02.09. Промт для LLM глубокого ресёрча (Gemini Deep Research /
ChatGPT Deep Research / Claude Research). Цель: знать в лицо
строителей ИИ-агентов — операторов, инженеров, идеологов. Результат
используется для: персональных писем (docs/LETTERS_DRAFT.md),
постов в Moltbook, питчей, приоритизации контактов.

---

## ПРОМТ (копировать отсюда целиком)

Ты — исследователь экосистемы ИИ-агентов. Задача: построить
галерею портретов ЛЮДЕЙ, которые реально делают автономных
агентов (не компаний, а людей в лицо). Не summaries из пресс-релизов
— живые портреты по их собственным словам и коду.

### Кого включать (три типа, до 40 человек суммарно)

1. ОПЕРАТОРЫ ДРАЙВЕРОВ: люди, которые ежедневно запускают агентов
   в сторонние системы/игры/рынки (участники хакатонов ETHGlobal
   2026, водители ботов на аренах, операторы торговых агентов).
2. СТРОИТЕЛИ ИНФРАСТРУКТУРЫ: авторы репутационных реестров,
   agent-фреймворков, стандартов идентичности (ERC-8004, ENS,
   agent-профили), протоколов микроплатежей (x402).
3. ИДЕОЛОГИ/ГОЛОСА: люди, формирующие мышление сообщества (публичные
   дискуссии о доверии к агентам, оркестрации, безопасности).

### Источники (в порядке приоритета)

- Moltbook (moltbook.com) — посты и треды: искать по темам
  «agent trust», «evidence», «orchestration», «hand-offs»,
  «permission prompts»; фиксировать НИК автора дословно.
- ETHGlobal showcase (ethglobal.com/showcase) 2025-2026: у проектов
  брать имена авторов со страниц проектов и их GitHub.
- GitHub: профили авторов, README, коммиты (активность = живость).
- X/Twitter: аккаунты, привязанные к проектам; что репостят, с кем
  спорят.
- YC-компании из кластера «agents/simulations/arenas» (Olam Labs,
  CoArena и соседи) — брать фаундеров, не компании.
- Discord/Telegram сообществ (Agentic, AI_PLAN, хакатонные) — только
  если публично.

### Карточка персоны (обязательные поля, отсутствие = пометка «нет данных»)

1. Имя/ник и где сидит (платформа + хэндл).
2. Что построил (1-2 предложения, конкретно: проект/продукт).
3. Человек или команда за ником; роль (фаундер/инженер/исследователь).
4. Три собственных цитаты (дословно, с ссылкой на пост/README) —
   как думает, во что верит.
5. Привычки: какие инструменты/стек упоминает; на каких площадках
  активен; с кем публично взаимодействует (2-3 имени).
6. Боль/раздражитель: что публично критикует (п拿出 пример).
7. Триггер интереса: что может зацепить предложением об арене
  политэкономии для агентов (судейство без LLM, датасет партий,
  ставки, HTTP без кошелька).
8. Ранг влияния: A (формирует мнение сотен), B (активный строитель),
  C (рядовой участник) — с обоснованием в одну строку.
9. Проверяемость: ссылка-источник на каждое утверждение.

### Правила честности (жёстко)

- Только проверяемые факты с ссылками. Нет источника — не пишем.
- Не выдумывать цитаты: каждая цитата = ссылка на пост.
- Если человек под ником и имя неизвестно — работаем с ником,
  не угадываем личность.
- Помечать дату каждого источника (контент старше 2025 помечать
  «устарело, актуальность проверить»).
- Разделять ФАКТ (написал проект X) и ИНТЕРПРЕТАЦИЮ (вероятно,
  зацепит арену) — интерпретации только в поле 7 и с словом «гипотеза».

### Формат вывода

1. Таблица-оглавление: ник | тип (оператор/строитель/идеолог) |
   проект | ранг A/B/C.
2. Карточки персон по шаблону выше, отсортированные по рангу.
3. Топ-10 «первая волна писем» — кого звать на арену первым и
   одной строкой почему (гипотеза).
4. Что не нашлось: список пустых зон (типы данных, которых в
   публичном доступе нет) — чтобы не принимать отсутствие за факт.

### Контекст для поля 7 (что такое alashi, одной строкой)

Alashi — ончейн-арена политэкономии для ИИ-агентов: 2-6 фракций,
рынок с падающей ценой, голосуемые законы, взятки, лицензии,
сеттл с рейком; судейство детерминировано кодом (ноль LLM),
каждая партия — воспроизводимый датасет (replay байт-в-байт),
вход по HTTP без кошелька.

## Как использовать результат

- Карточки поля 7 → персонализация docs/LETTERS_DRAFT.md
  (шаблоны А/Б/В уже сегментированы).
- Ранг A → сегмент В писем (исследователи/голоса), B → сегмент А,
  реестры → сегмент Б.
- Пустые зоны (раздел 4) → чему учить собственных агентов-скаутов
  (Moltbook-краулер уже умеет собирать посты).
