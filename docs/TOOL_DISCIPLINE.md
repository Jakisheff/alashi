# TOOL_DISCIPLINE: старая машина занятого человека (рамка владельца 03.09)

Теория: миллионеры на старых машинах, не скромность и не дауншифт:
Машина была нормальной, когда покупалась, а дальше человек был
Занят делом. Менять постоянно: это хобби-шопингомания («увлекаться
Часами = покупать часы»), свойственная узкой группе и отдельным
Странам; не все ей страдают. Увлечение делом ≠ потребление
Инструментов.

## Применение к alashi: наш стек, старая машина, которая везёт

Голый Rust без фреймворков, HTTP-сервер на std::net, curl вместо
SDK, litesvm вместо тяжёлой инфраструктуры, арена на ноутбуке за
Туннелем. Это не отсталость: это занятость продуктом вместо
Обновления парка. И это часть честного бутстрап-нарратива для жюри:
Нулевая стоимость инфраструктуры, всё воспроизводимо.

## Правила канона

1. ИНСТРУМЕНТ НЕ МЕНЯЕТСЯ, ПОКА РЕШАЕТ: новый стек/фреймворк/цепочка/
 модель подключаются только когда старый «развалился» (не тянет
 нагрузку, фичу или безопасность), не потому что вышел новый.
 Модно ≠ нужно.
2. АНТИ-ШОПИНГОМАНИЯ В ТЕХНОЛОГИЯХ: «увлекаться агентами» не значит
 перепробовать все фреймворки; мера инженера, глубина освоения
 немногих инструментов (согласовано с LEARNING_CURVE: кривая
 осваивается, а не перезапускается).
3. ТЕСТ НОВОЙ ИГРУШКИ: «какую задачу продукта это решает, которую
 текущий инструмент не решает?», без конкретной задачи внедрение
 запрещено; идея без задачи идёт в IDEAS_PARKED с условием запуска
 «когда текущий развалится».
4. Окно до демо, особенно строго: никаких переездов (облако, новый
 RPC, переписывание арены), кроме случаев фактического развала
 (туннель умирает, домен уже в задачах прямой).

Согласование: BRAND_DNA (аранжировки да, смена жанра нет),
LUCK_RISK (заготовки важнее новых инструментов), FAIR_EARNINGS
(экономность не прячем: это нарратив), POSITIONING (прямая: не
Создавать кривую ради кривой).
