# Falsify Harness (жёсткий харнесс проверяющего слоя)

Превращает фальсификацию из ритуала в измеримую процедуру с числами.
Основан на живом прогоне 23.11 (commitment 679c2fa1, батарея 5/5,
поймана ложная журнальная запись) и всех фальсификационных раундах
22-23.11. Протокол:

1. COMMIT: план и seed фиксируются ДО всего (plan_hash со свежей солью).
2. SEED: батарея мутантов выбирается каталогом по seed, производному от
   plan_hash — задания выбирает протокол, не человек.
3. INJECT: мутанты вносятся в изолированный worktree.
4. CHECK: два режима —
   - selfcheck: каждый мутант ОБЯЗАН ронять свой детектор-тест
     (мутационная стойкость набора; это жёсткий CI-гейт);
   - audit: готовит нейтральное досье для слепого внешнего исполнителя
     (промпт без словаря проекта; covert-канал лексики разорван,
     JS≈1.0 к коммит-месседжам) и принимает отчёт.
5. REVEAL: сверка плана с commitment (тампер = провал), recall батареи
   против порога; exit-код ненулевой при любом нарушении.

Порог: selfcheck — 100% kill; audit — recall ≥ 80%, FP = 0 на чистом
контроле. Правило fix-killer: фикс без мутанта-убийцы не принимается
(мутант обязан быть в каталоге).

## Использование

    python3 tools/falsify/harness.py commit            # фиксирует план+seed
    python3 tools/falsify/harness.py battery           # показывает выборку
    python3 tools/falsify/harness.py selfcheck         # CI-гейты: kill 100%
    python3 tools/falsify/harness.py audit --prepare   # досье для слепого аудитора
    python3 tools/falsify/harness.py audit --report F  # приём отчёта, recall
    python3 tools/falsify/harness.py reveal            # проверка commitment

Каталог мутантов расширяется только новыми ДОКАЗАННЫМИ дефектами
(находка фальсификации → рецепт → киллер-тест). Мутант без работающего
детектора в каталог не попадает — это и есть fix-killer правило.
